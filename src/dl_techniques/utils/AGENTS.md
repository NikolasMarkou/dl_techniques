# Utils Package

Shared utilities used across the library — tensor operations, geometry, masking, alignment, and more.

## Structure

### Top-level Modules
- `tensors.py` — Core tensor ops: `gram_matrix()`, `power_iteration()`, `window_partition()`/`window_reverse()`, `l2_normalize()`, Gaussian kernels, orthonormality validation. Also the shared home for pure dimension-contract helpers that used to be private copies in `layers/` and `models/`:
  - `is_power_of_two(n)` — `True` only for `n >= 1` with one set bit, so `0` and negatives are rejected. Used by `layers/orthogonal_butterfly.py` and `layers/norms/polar_weight_norm.py` to refuse a last dimension they cannot pair. `polar_weight_norm._next_power_of_two` is a different function and stays where it is
  - `make_divisible(value, divisor=8)` — the MobileNet channel-width rounding rule (torchvision `_make_divisible`, Keras Applications `_depth`): nearest multiple of `divisor`, at least `divisor`, one step up when rounding fell more than 10% below. One home for what were private copies in `models/vision/mobilenet/mobilenet_v2.py` and `mobilenet_v3.py`; also `SqueezeExcitation(divisor > 1)`'s bottleneck width
  - `canonical_binary_input_shape(input_shape)` — collapses one-shape-or-list-of-shapes into the single shape a binary elementwise layer builds from, raising on more than two shapes or on a mismatched pair. Used by `layers/logic/{logic,arithmetic}_operators.py` from three sites each (`build`, `compute_output_shape`, `_assert_call_shape_contract`). Import it by its bare name: `tests/test_layers/test_logic/test_the_nine_source_fixes_stay_fixed.py` asserts the call sites resolve as `ast.Name`, so a qualified `tensors.canonical_binary_input_shape(...)` call would go unseen. It is NOT the `is_list_of_shapes` idiom inlined three times under `layers/attention/`, which is deliberately kept separate
  - `l2_normalize(x, axis, eps)` — divides by `max|x|` **before** squaring, so the result is a unit vector at every input scale. **Prefer it over inlining `x / sqrt(sum(x**2) + eps)`**: that spelling fails silently at both ends of the scale — above `sqrt(float32_max) ~ 1.84e19` the squared sum is `inf` and the output is exactly `0.0` (finite, so no warning, and no directional signal), and around `1e-8` the `eps` dominates the norm so the output is not a unit vector at all. Measured error against a float64 oracle, float32: naive `9.5e-01` at `1e-8` and at `1e+20`, against `8.5e-08`–`1.1e-07` for this helper across `1e-33` to `1e+38`. It does **not** rescue input already below ~`1e-33` (a dtype limit — the naive form is equally bad there) and it does **not** repair an `inf`/`NaN` input. Zero rows return zeros through the DIVISOR substitution alone (`1` for a zero `peak`), not through a trailing `ops.where` and not through a floored divisor: `peak == 0` implies the pre-scaled vector is already `0`, the norm is `sqrt(eps)`, and `0 / sqrt(eps)` is the correct `0` with nothing further. A trailing `ops.where` was present and has been REMOVED -- mutation testing found deleting it changed nothing at all (bit-identical on zero, ordinary, `1e-30`, `1e30` and mixed zero/huge rows), which makes it dead code that only LOOKS like a safety net; see `tensors.py`'s docstring and `layers/structured_linear/MIGRATION.md` §"`l2_normalize` — a redundant guard removed". A floored divisor does not work either: any floor above min-normal clamps real data, and any floor below it is subnormal, where `0/subnormal` rounds to `nan`. **~60 files under `src/` still inline the naive idiom**; migrating them is deliberately NOT done in one sweep, so this entry is the discoverability record rather than a claim of universal adoption
- `constants.py` — Shared constants for config keys
- `random.py` — `rayleigh()` distribution generator with statistical validation
- `logger.py` — Centralized library logger
- `bounding_box.py` — IoU (GIoU/DIoU/CIoU), format conversion, NMS
- `corruption.py` — 10 image corruption types (noise, blur, distortion, color) with severity levels, backend-agnostic
- `inference.py` — `FullImageInference`: sliding window patch extraction + aggregation for YOLOv12, with profiling
- `tokenizer.py` — `TiktokenPreprocessor`: BERT-compatible tokenization with special tokens, attention masks
- `deep_supervision.py` — Deep-supervision output helpers (auxiliary heads, weight scheduling glue)
- `drop_path.py` — `linear_drop_path_rates(num_blocks, max_rate)`: computes per-block stochastic-depth (drop-path) rates for transformer/ConvNeXt block stacks. The actual drop-path layer is `StochasticDepth` in `dl_techniques/layers/stochastic_depth.py`
- `weight_transfer.py` — three loaders, deliberately not interchangeable:
  - `load_weights_from_checkpoint(target, ckpt_path, skip_prefixes, strict, allow_unloaded=None, vocab_change=None)`: layer-by-layer *partial* transfer between different architectures (a pretrain trunk into a fine-tune model). Use this instead of `model.load_weights(by_name=True)` (broken in Keras 3.8 for `.keras` files). A zero-layer result **reports rather than raises** — `src/train/beit/` and `src/train/energy_transformer/` build their own warm-start guards on that report. Passing `allow_unloaded=<prefixes>` makes it complete-or-raise instead, in both directions: every weight-bearing target layer not skipped by prefix must load, and every weight-bearing checkpoint layer not skipped by prefix must have a target layer (a deeper checkpoint raises), except those prefixes; a raise copies nothing. `vocab_change` (a `VocabChange`) transfers the named vocabulary layers variable by variable: equal shapes copy, a variable keeps its init (`report.vocab_fresh`, logged at WARNING) only when its path ends with one of `VocabChange.tables` (what it IS) AND its shape differs only by the vocabulary size, anything else is a mismatch (a resized position table raises)
  - `read_checkpoint_config(path)` / `vocab_change(path, vocab_size, layers, tables)`: read a `.keras` archive's own `config.json`, so a loader can decide from the checkpoint (e.g. its `vocab_size`, or H-Net's `arch_config.vocab_size`) rather than from a class default
  - `load_backbone_from_checkpoint(target, ckpt_path, head_prefixes, vocab_layers, tables, tops=(), allow_vocab_change=True)` (`tables` = variable-path suffixes of the token table and untied output, required, no shape-only default): the language models' `pretrained=<path>` load rule in one place (see `models/language/AGENTS.md`), built on the two above; every class with that route calls it
  - `pretrained_path_or_raise(pretrained, model_label)` / `refuse_pretrained(pretrained, model_label)`: the two readings of a `from_variant(pretrained=...)` argument. The first returns `None` for falsy, the existing path for a `str`, and raises `NotImplementedError` for `True` (language models, which load a backbone from a path). The second raises `NotImplementedError` for every truthy value, a path included, for a model with no backbone/head split whose whole-archive load is `keras.models.load_model(path)` (CLIP, MobileCLIP v1/v2, NanoVLM, CliffordCLIP, SAM 1 to 3, the ideogram4 and SD3 factories, `create_shared_token_decoder`). A model for which that advice is wrong passes its own sentence as the third argument, `how_to_load` (the RBF pair does: its pre-change archives are refused by `load_model`, and `model.load_weights(path)` restores them); the docstring lists every caller, and `tests/test_utils/test_model_build.py::test_the_documented_callers_are_the_real_callers` compares that list with the AST
  - `load_pretrained_checkpoint(model, weights_path, build_shape, skip_mismatch=True, head_pattern=DEFAULT_HEAD_PATTERN, ignore_config_keys=DEFAULT_NON_STRUCTURAL_CONFIG_KEYS)`: a model's own `pretrained=<path>` load, the shared body for a model's `load_pretrained_weights`. Raises `FileNotFoundError` for a missing file; builds the model at `(1, *build_shape)` only when it is unbuilt (a built model keeps its variables), and for an unbuilt model refuses a `build_shape` whose last axis is `None` with a `ValueError` naming `input_shape` and the tuple (`require_channel_count`, below) instead of the first convolution's "unsupported operand type(s) for %". Three checks run before any weight is copied, so a refused load copies nothing into the model (it does not always leave an unbuilt model as it was: the configuration check runs before the build and leaves it unbuilt, but the layer and head checks need the built layers, so an unbuilt model they refuse is left built, at its own initialization). **Layers:** it transfers through `load_weights_from_checkpoint` with no skipped prefix and `allow_unloaded_pattern=head_pattern`, so **every layer outside the head must load**: only layers whose WHOLE name matches `head_pattern` (default `classification_head` or `supervision_head_{i}`, the names the house-shape naming guard enforces; a trunk layer called `classification_head_proj` is not a head) may have another shape (another `num_classes`), be missing from the checkpoint (a headless checkpoint) or be absent from the model (a headed checkpoint into `include_top=False`), and a head left at its initialization is logged as a warning. A trunk layer of another shape or missing, or a checkpoint layer with no home (a wrong variant, block type, width, stem, a deeper or shallower one) raises `ValueError` naming the first 8 offending layers with the report counts. **Configuration (D-041, D-044):** when the archive records a config of the model's own class (`read_checkpoint_config`), or is a functional wrapper holding exactly one layer of that class (what `train_resnet.py` saves as `inference_model.keras`: `keras.Model(inputs, model(inputs))`), every constructor-config key present on BOTH sides and outside `ignore_config_keys` must be equal (values as plain JSON data, tuples read as lists, an integer `n` and the pair `[n, n]` read as one value: `kernel_size=7` is `(7, 7)`, while `[7, 5]` is another kernel), else `ValueError` names each key with both values. Equal shapes do not make equal architectures (ReLU against GELU, another `shifts`, `ctx_mode` or `strides` all fit). A key only one side holds is unknown, not a difference (an argument added since the archive was written still loads; one the class has removed or renamed fails earlier, when Keras rebuilds the archive's model from its config, with a `ValueError` naming it, as MobileNet's `weight_decay` does for archives written before it became `kernel_regularizer`); an archive in which no single model of that class can be found (a checkpoint of other code, a wrapper around two such models) is checked by layers only and the load logs a warning saying the configuration was not compared; a Sequential or functional TARGET (its config lists generated layer names) is checked by layers only without one. **Head (D-044):** `head_config_overrides` is NOT among the default ignored keys, because it can change what the head computes and no weight shape (`pooling_type` max against avg, equal shapes: ConvNeXt V1 outputs 0.15 apart and RAD 0.30 on the contract's tiny configurations before the check, `scratch_iter2/step13_2/loader_probe_before.txt`). It is compared exactly (leaving out `NON_STRUCTURAL_HEAD_CONFIG_KEYS`: dropout, initializers, regularizers) only when the head layer would be copied, that is when every one of its weight shapes fits; a head the shapes exclude (another `num_classes`, another `block_dims`), a headless target and a headless checkpoint are not compared, so fine-tuning with a new head still works. Spell the head the way it was saved: a default written out on one side only is a difference. A caller that wants the weights in a head that computes another function names `head_config_overrides` in `ignore_config_keys`. Each model declares the keys that leave the weight layout and the function alone as a module constant `_NON_STRUCTURAL_CONFIG_KEYS` built on `DEFAULT_NON_STRUCTURAL_CONFIG_KEYS` (`name`, `trainable`, `dtype`, `num_classes`, `include_top`): initializers, regularizers, dropout and stochastic-depth rates, `input_shape`, `layer_scale_init`, ResNet's `enable_deep_supervision`. `skip_mismatch=False` allows no layer difference at all, head included. Also raises `ValueError` chained to the original error when the build or the transfer fails, and `ValueError` when it restores no layer (a model whose every weighted layer is a head). It is a third function, not a change to the transfer function, for the same reason as `load_weights_or_raise` (the D-070 anchor); the layer rule is anchored `D-040`, the config rule `D-041`, the wrapper and head rules `D-044`. It returns the `TransferReport`; the models' `load_pretrained_weights` return `None`. `load_weights_from_checkpoint` gained `allow_unloaded_pattern` (a regular expression a layer name must match in full, in addition to the `allow_unloaded` prefixes) and `before_copy` (a callable given the finished report before the first weight is copied; raising from it copies nothing) for it
  - `plain_head_config_overrides(head_config_overrides, class_name)` (`model_build.py`): the vision classifiers' constructor copy of `head_config_overrides`. `None` or empty returns `None`; a value that is not JSON data (a live regularizer or initializer) raises `ValueError` naming the key, because `json.dumps(model.get_config())` would otherwise fail long after the mistake; pass the name or `keras.regularizers.serialize(...)`
  - `coerce_include_top(include_top)` and `validate_rates(**rates)` (`model_build.py`): the argument checks the vision classifiers share, called at the top of each `__init__`. The first returns a `bool` and refuses anything but a `bool` or `numpy.bool_` with `TypeError` naming the value and its module-qualified type (`bool("no")` is `True`, which built a headed model for `include_top="no"`; `numpy.bool_` is coerced so `get_config` stays JSON-safe). The second takes each rate under its constructor-argument name, `validate_rates(dropout_rate=..., drop_path_rate=...)`, and raises `ValueError` "<name> must be in [0, 1), got <value>" for a value outside `[0, 1)` (`nan` included), so the message names the caller's argument and not the ramped value a sub-layer would report. Its callers are `CliffordNet`, `HierarchicalCliffordNet`, `RADConvNet`, `RBFProtoNet`, `CliffordRBFProtoNet`, `SqueezeNetV1`, `SqueezeNoduleNetV2`, `_ConvNeXtBase`, `DeepSortAppearanceNet` and `DeepSortResidualBlock`; the count rule of the same models is `utils/validation.positive_int` (`positive_int(num_classes, "num_classes", type(self).__name__)`), which refuses a bool, a float, a string and `None`
  - `refuse_input_shape(kwargs, class_name, reason)` (`model_build.py`): raises `ValueError` naming the keyword, the class and `reason` when `kwargs` holds `input_shape` or `input_dim`. Called first in the constructor of each layer or subclassed model that has no `input_shape` parameter (`RBFProtoNet`, `CliffordRBFProtoNet`, `UcaEncoder`, `MambaLCT`, `ConvUNextStem`, `CliffordNet`, `HierarchicalCliffordNet`, `DeepSortAppearanceNet`, `DeepSortResidualBlock`, `CosineClassifier`, `SiamFC`, `SiamFCBackbone`, `DaSiamRPN`, `SiamRPNBackbone`), because `keras.layers.Layer.__init__` pops both keywords and only warns, so a caller written against an older signature kept building a model that ignored the shape. Every other unknown keyword is refused by Keras itself. Pinned by the `no_shape_keyword_swallowed` rows of `tests/test_models/test_the_vision_classifiers_share_one_runtime_contract.py`
  - `require_channel_count(input_shape)` (`model_build.py`): refuses an unbatched `input_shape` that is empty or whose last axis is `None`, with a `ValueError` carrying `input_shape=<tuple>`; the spatial axes may be `None`. Called by `load_pretrained_checkpoint` before it builds an unbuilt model and by the `from_variant` of `CliffordNet` and `HierarchicalCliffordNet` and the constructors of `SqueezeNetV1` and `SqueezeNoduleNetV2`, which build whenever they are given a shape (the other classifiers only store it)
  - `load_weights_or_raise(model, weights_path, skip_mismatch)`: whole-file `.keras` restore into the **same** architecture, returning the number of variables whose value changed and raising when that is zero. `model.load_weights(path, skip_mismatch=True)` restores nothing and returns normally when names or shapes do not match, so never call it bare
- `sequence_length_guard.py` — refuses a sequence longer than a model's position limit on every path, for models with a real limit (a learned position table, a precomputed RoPE table). Three guard functions plus an error type, a helper and a load mixin (BERT, DistilBERT, FNet, ModernBERT, TreeTransformer, GPT2, TopoLM, WaveFieldLLM, Qwen3, Qwen3Next, Gemma3, Zamba2, HNet and BLT call the guard functions; Mamba and Mamba2 have no position limit and are not guarded):
  - `SequenceLengthError(ValueError)`: what the refusal raises. A subclass only so a wrapper whose `build` builds a guarded backbone (`CausalLanguageModel`, `MaskedLanguageModel`) can catch exactly a length refusal, call `drop_cached_step_functions(self)` and re-raise; every caller catching `ValueError` is unchanged
  - `RecordedBuildShapeMixin`: listed FIRST among the bases of every guarded model except BLT (`class BERT(RecordedBuildShapeMixin, keras.Model)`). Its `build_from_config` sets `_loading_recorded_build_shape` on the model and on every `_flatten_layers()` layer that declares it (`TextDecoder`, `PositionalEmbedding`), delegates to Keras, and clears it in `finally`. Keras 3.8 runs that rebuild from the archive's recorded shape inside a bare `try/except` and marks the model built anyway, so a refusal there loaded an archive recorded past the limit with NO weights; with the mixin it logs a warning and loads every weight. No config key, no registration; BLT keeps its own `build_from_config` with the same effect. Pinned by the archive arm of `tests/test_models/test_a_position_limit_is_refused_cleanly.py`
  - `drop_cached_step_functions(model)`: sets `model.predict_function`/`train_function`/`test_function` to `None`; each model, a wrapper included, caches its own
  - `refuse_static_sequence_length(model, seq_len, limit, message)`: no-op for `None` or `seq_len <= limit`; otherwise raises `SequenceLengthError(message)`, first nulling `model.predict_function`/`train_function`/`test_function` only when the model is not yet built (a built model keeps them: `fit` makes `train_function` once before its epoch loop, so a refusal caught by a callback mid-fit must not drop it). Call it from `build` BEFORE any variable exists: a refusal raised inside the first trace of Keras's cached step function leaves that function, and so the model, unusable for every later call. While `model._loading_recorded_build_shape` is set (only by `RecordedBuildShapeMixin.build_from_config`) it logs `message` as a warning and returns
  - `gate_dynamic_sequence_length(input_ids, limit, message, limit_name)`: for a sequence axis that is `None` (a relaxed `predict`/`fit` retrace). Returns the input unchanged off TensorFlow or for a `KerasTensor`; in a TF graph it adds a zero term sized `limit - seq_len` behind a run-time assertion. XLA (Keras's `jit_compile="auto"` default whenever a GPU is visible) drops the assertion, and a gather-based position table then returns FINITE GARBAGE; the zero term fails the XLA compile naming `seq_len_exceeds_<limit_name>_<limit>`, so do not delete it. Pinned by `tests/test_models/test_a_position_limit_is_refused_cleanly.py` (one `Subject` row per model; forces the XLA resolver)
  - `check_sequence_length(model, input_ids, limit, limit_name, message)`: the one line a model's `call` carries, right after it resolves `input_ids`. Routes a static length to the refusal and a `None` axis to the gate; `message` is a `str.format` template with `{seq_len}` and `{limit}`. A model whose `build` traces `call` via `materialize_sublayers` needs nothing else (the trace refuses before any sub-layer is built); a model that builds sub-layers by hand (BERT, TopoLM, Zamba2, HNet, BLT) also calls `refuse_static_sequence_length` first in `build`; WaveFieldLLM builds everything in `__init__` and needs only the `call` line. A model whose limit exists only for some configurations guards only those: Zamba2 only with a `g` position in `layer_mapping`, HNet only when stage 0 (the encoder/decoder, or the single stack of a one-stage layout) has an attention block (inner stages see at most `max_chunks` positions). Every guarded model warns and builds when an old archive recorded an over-long shape (`RecordedBuildShapeMixin`; BLT through its own `build_from_config`)
- `conformal_classification.py` — split-conformal prediction sets for a classifier (Adaptive Prediction Sets), numpy only: `calibrate_aps`, `predict_sets`, `evaluate_sets` (coverage, set size, empty rate, class-conditional coverage) and `repeated_split_coverage` (the empirical check over random 50/50 splits). Takes logits. Reuses `conformal_quantile` from `conformal_denoiser_intervals.py`. `randomized=False` (`u = 1`) is the rule `layers/statistics/conformal/prediction_set.py` runs in-graph, and the two are pinned equal by `tests/test_layers/test_statistics/test_conformal/test_prediction_set.py`. Coverage is marginal and needs a model that was not chosen on the calibration data. Tested by `tests/test_utils/test_conformal_classification.py`
- `yolo_decode.py` — YOLOv12 output decoder (anchors-free decoding to boxes + scores)
- `activation_serialization.py` — the canonical `activation`-argument (de)serialization pair, used directly by ~60 pre-existing files plus `layers/activations/common.py`'s wrapper trio (see `layers/AGENTS.md`):
  - `serialize_activation(activation)` — makes a stored `activation` value JSON-safe for `get_config()`. A `keras.layers.Layer` goes through `keras.saving.serialize_keras_object`; any other callable goes through `keras.activations.serialize`; **everything else — including a bare `str`, `None`, and a dl_techniques factory key like `'mish'`/`'sparsemax'` — passes through unchanged.** That passthrough is mandatory, not incidental: `keras.activations.serialize` raises on a bare string, and a factory key is not a Keras activation at all
  - `deserialize_activation(activation, custom_objects=None, allow_layer=True)` — inverts `serialize_activation`. A `dict` goes through `keras.saving.deserialize_keras_object` (dispatches both the function form and the Layer form); everything else — `str`, `None`, an already-live callable — is returned **unchanged** (this function does not resolve a bare string to a callable; that is `resolve_activation`'s job, see below)
    - `allow_layer` (default `True`): preserves the original, Layer-permissive contract all ~60 pre-existing callers rely on. Pass `allow_layer=False` only when the caller's contract must reject a `keras.layers.Layer` activation (weights created in `call()` rather than `build()` break `.keras` weight loading) — `layers/activations/common.py::resolve_activation` is the one caller that does this
  - **Call-site placement rule**: `serialize_activation` belongs in `get_config()`; `deserialize_activation` belongs in `__init__`, on the value's way into the stored attribute — **never in `from_config`**. MEASURED: `keras.models.load_model(..., custom_objects=...)` builds sub-objects inside a `custom_object_scope`, so the `custom_objects=None` default already resolves an unregistered function correctly from `__init__`; that call site additionally covers hand-rolled `Cls(**cfg)` reconstruction and nested layers whose parent never calls their `from_config`
  - Consumed directly by ~60 pre-existing files and, as of this plan (`plan-2026-09-15T034909-a7edc8da`), migrated onto by 37 further files via `layers/activations/common.py`'s wrapper — see `layers/AGENTS.md` for why those 37 go through the wrapper rather than this pair directly
- `matplotlib_backend.py` — `import_pyplot(with_cm=False)`: the one place library code acquires `matplotlib.pyplot`. **Setdefault semantics, not an override**: a non-empty `MPLBACKEND` is respected as-is; only when it is unset does the helper select `Agg` (via `matplotlib.use` *and* the env var, so subprocesses inherit it). Returns `plt`, or `(plt, cm)` when `with_cm=True`. All **five** matplotlib-using callbacks in `dl_techniques/callbacks/` go through it.
  - What it fixes is **divergence, not a crash**: three callbacks imported `pyplot` bare and two forced `Agg`, so the process-global backend depended on which plotted first. MEASURED on matplotlib 3.10.0: with `MPLBACKEND` unset a bare `import matplotlib.pyplot` resolves to `agg` on its own, with `DISPLAY` unset *and* with a bogus `DISPLAY=:99` (savefig OK) — matplotlib's own headless fallback. An earlier revision of this bullet claimed the bare importers "crashed on a headless host"; that claim was false and is retracted.
  - Scoped rule: **inside `dl_techniques/callbacks/`, never import `matplotlib.pyplot` directly** — use the helper. This is *not* yet a tree-wide invariant: `grep -rln "import matplotlib" src/dl_techniques --include=*.py` returns **29** files, of which **25** are outside `callbacks/` and outside the helper (all 10 of `analyzer/`, all 6 of `visualization/`, 2 in `datasets/`, `losses/clustering_loss.py`, `models/memory/som/model.py`, and 5 under `utils/`). None of the 25 is a Keras callback, so all are out of scope for the guard — but note that `callbacks/analyzer_callback.py` reaches matplotlib **transitively** through `dl_techniques.analyzer`, so an epoch hook does hit a bare import. Widening the guard to `analyzer/` is a separate, untaken decision.
  - The guard is `tests/test_callbacks/test_the_matplotlib_backend_is_headless.py`. Its subject list is a **derived AST census** of `callbacks/*.py` (not a hardcoded literal) with an anti-vacuity floor, and its behavioural arms run in fresh subprocesses whose `MPLBACKEND` the harness sets explicitly — the suite itself runs under `MPLBACKEND=Agg`, so an in-process assertion would read the environment rather than the code

## Conventions

- `__init__.py` is empty — import from submodules directly
- Subpackages with `factory.py` support config-driven construction
- Geometry utilities support hyperbolic space operations used by graph models
