## 1. Philosophy and Motivation

### 1.1 The failure modes JEPA responds to

Self-supervised learning before JEPA split into two families, each with a structural weakness.

**Generative / reconstructive (MAE, BERT, GPT, VideoMAE):**

- Reconstruct pixels or tokens directly in input space.
- Must model *all* variation, including noise, lighting, texture, grain.
- Capacity is spent on unpredictable low-level detail.
- Pixel-level loss averages over the many possible completions, producing blurry, uncommitted predictions.

**Contrastive / invariance-based (SimCLR, CLIP, DINO, BYOL):**

- Learn invariance to hand-crafted augmentations.
- The augmentation set encodes human priors about what *should* be invariant.
- Information useful downstream may be discarded by construction.
- Typically require careful negative sampling or multi-view engineering.

### 1.2 LeCun's argument

JEPA was proposed by Yann LeCun in the 2022 position paper *A Path Towards Autonomous Machine Intelligence* as the substrate for learned world models. The complaint is specific: **predicting the input is the wrong objective.** The canonical example is video. Predicting every pixel of a future frame is close to impossible because of chaotic high-entropy detail such as flickering leaves or ripples on a pond. A predictor operating in representation space can *choose to ignore* detail that is neither predictable nor relevant, so the encoder learns to discard what does not matter and retain what is needed to predict what comes next.

In information-theoretic terms the representation is a **lossy compression** of the input that keeps only the structure which reduces uncertainty about the target. LeCun connects this to predictive coding in cortex, where neurons encode surprising deviations and higher-order features rather than raw sensory values.

### 1.3 JEPA as an energy-based model

The deeper architectural claim is that JEPA is an **energy-based model**, not a probabilistic generator. It cannot be sampled from; it captures dependencies between $x$ and $y$ without generating $y$. The energy

$$
F(x, y) = \left\| g_\phi(s_x, z) - s_y \right\|^2
$$

is low for compatible pairs and high for incompatible ones. This sidesteps the curse of dimensionality that afflicts generative models in continuous multimodal domains: instead of placing probability mass over every possible future, you shape an energy landscape, and the latent variable $z$ carries residual information about $y$ that cannot be recovered from $x$.

Two consequences run through the rest of this document:

1. Every JEPA loss lives in embedding space.
2. Every anti-collapse mechanism exists because an EBM trained without contrastive samples will otherwise flatten its energy surface.

### 1.4 The critique of autoregressive LLMs

LeCun treats token-by-token autoregression as a conceptual dead end for Advanced Machine Intelligence:

- Fixed compute per token, no deliberation before committing to output (System 1, reactive).
- No abstract space in which to plan.
- Error compounds with sequence length, because each token is drawn from surface statistics rather than from a world model.

JEPA is intended as the world-model substrate on which a separate reasoning and planning module performs energy minimization (System 2) before anything is emitted. **H-JEPA** stacks JEPAs across time scales so the same machinery plans at both "contract the quadriceps" and "cross the road" levels of abstraction. See [Section 12](#12-h-jepa-hierarchical-planning).

### 1.5 Comparison table

| Aspect | Generative | Contrastive | JEPA |
|---|---|---|---|
| Prediction target | Raw pixels / tokens | View agreement | Abstract embeddings |
| Handling of uncertainty | Poor (blurry average) | Sidestepped | Natural (encoder drops noise; $z$ absorbs residual) |
| Decoder required | Yes | No | No |
| Augmentation dependence | Low | High | None required |
| Representation level | Often low-level | Invariant, possibly lossy | Semantic by design |
| Compute profile | Decode everything | Multiple views | Single view, partial encode |

### 1.6 The Moravec paradox connection

The Moravec paradox observes that what humans find easy (perception, motor control) is hard for machines, while what humans find hard (arithmetic, formal manipulation) is easy. JEPA targets the hard half directly: learning from passive observation the way infants do, building an internal world model, prioritizing semantic understanding over surface reconstruction, and enabling planning in an abstract space.

## 2. Core JEPA Architecture

### 2.1 Block diagram

```
+---------------------------------------------------------------------+
|                     JEPA CORE ARCHITECTURE                          |
|                                                                     |
|   +---------------+                                                 |
|   |   Input x     |  visible portion of image / video / spectrogram |
|   |   (context)   |                                                 |
|   +-------+-------+                                                 |
|           |                                                         |
|           v                                                         |
|   +---------------+                                                 |
|   |   Context     |  trainable encoder                              |
|   |   Encoder f_t |  (typically ViT)                                |
|   +-------+-------+                                                 |
|           |                                                         |
|           v                                                         |
|   +---------------+     +---------------+                           |
|   |   Context     |     |  Positional / |                           |
|   |   Embedding   | + --|  mask tokens z|  (where to predict)       |
|   |      s_c      |     |               |                           |
|   +-------+-------+     +---------------+                           |
|           |                                                         |
|           v                                                         |
|   +---------------+                                                 |
|   |   Predictor   |  trainable, narrower than the encoder           |
|   |      g_phi    |  outputs predicted target embeddings            |
|   +-------+-------+                                                 |
|           |                                                         |
|           v                                                         |
|   +---------------+         +---------------+                       |
|   |   Predicted   |         |   Target      |                       |
|   |   Embedding   |<--Loss->|   Embedding   |                       |
|   |    s_hat_t    |         |     s_t       |                       |
|   +---------------+         +-------+-------+                       |
|                                     ^                               |
|                             +-------+-------+                       |
|                             |    Target     |  EMA of context       |
|                             |   Encoder     |  encoder, stop-grad   |
|                             +-------+-------+                       |
|                                     ^                               |
|                             +-------+-------+                       |
|                             |   Input y     |  masked / target      |
|                             |   (target)    |  region               |
|                             +---------------+                       |
+---------------------------------------------------------------------+
```

### 2.2 Components

**Context encoder $f_\theta$**

- Usually a Vision Transformer.
- Processes only the visible (unmasked) patches, which is where much of the compute saving comes from.
- Fully trainable; this is the only module kept for most downstream use.
- Emits a sequence of patch embeddings.

**Target encoder $f_{\bar\theta}$**

- Same architecture as the context encoder.
- Weights are an exponential moving average of the context encoder's weights.
- Stop-gradient applied: no backpropagation through this branch.
- Processes the target regions in unmasked form.

**Predictor $g_\phi$**

- Shallower and narrower transformer than the encoders.
- Consumes context embeddings plus conditioning $z$ describing *where* (and for action-conditioned variants, *under what action*) to predict.
- Deliberately under-powered relative to the encoder. A predictor that is too strong can absorb the task and let the encoder degenerate.

**Latent / conditioning variable $z$**

- Carries the information about $y$ that is genuinely not recoverable from $x$: target position, target time span, an action, a text prompt.
- In the EBM framing, $z$ is what keeps the energy landscape from having to be single-valued.

### 2.3 Information flow

```
Training step
  1. Sample input (image, clip, spectrogram, text pair)
  2. Generate context mask and target mask(s)
  3. Context encoder: visible patches -> s_c
  4. Target encoder (EMA, no grad): target patches -> s_t
  5. Predictor: (s_c, z) -> s_hat_t
  6. Loss: distance between s_hat_t and stop_grad(s_t)
  7. Backprop: update context encoder + predictor
  8. EMA: update target encoder from context encoder

Inference (downstream)
  - Context encoder only
  - Predictor discarded, except for world-model rollouts and planning
  - Features consumed by a linear probe, attentive probe, or fine-tuned head
```

### 2.4 Loss variants used in practice

```python
# L2 / MSE: the default (I-JEPA, base formulation)
L = mean((s_hat - s_target) ** 2)

# L1: used in V-JEPA
L = mean(abs(s_hat - s_target))

# Smooth L1 (Huber): robust to outlier target dimensions
L = smooth_l1(s_hat, s_target)
```

Why a plain regression works at all, given that the target is also learned:

- The EMA teacher supplies slowly-moving, hence stable, targets.
- Stop-gradient removes the shortcut of moving the target toward the prediction.
- The predictor bottleneck prevents the pair from colluding.
- High masking ratios keep the task non-trivial.

## 3. The Unified Objective

Every variant in this document instantiates one template:

$$
\mathcal{L}
= \underbrace{\left\| g_\phi\!\left(f_\theta(x_c),\, z\right) - \mathrm{sg}\!\left[f_{\bar\theta}(x_t)\right] \right\|_2^2}_{\text{latent prediction}}
\;+\;
\underbrace{\lambda\, \mathcal{R}\!\left(\{s_i\}\right)}_{\text{anti-collapse}}
$$

with $\mathrm{sg}[\cdot]$ the stop-gradient operator, and the EMA update

$$
\bar\theta \leftarrow \tau\,\bar\theta + (1-\tau)\,\theta,
\qquad \tau \in [0.99,\ 0.9999]
$$

Variants differ only in how $x_c$ and $x_t$ are constructed, how the target branch is parameterized, and which regularizer $\mathcal{R}$ is used.

| Variant | $x_c,\, x_t$ | Target encoder | Anti-collapse $\mathcal{R}$ | Conditioning $z$ |
|---|---|---|---|---|
| I-JEPA | Image patch blocks | EMA of $\theta$ | EMA + stop-grad + bottleneck | Target block position |
| V-JEPA | Video tubelets | EMA of $\theta$ | EMA + stop-grad + bottleneck | Tubelet position (space, time) |
| V-JEPA 2 | Video tubelets, 3D-RoPE | EMA of $\theta$ | EMA + stop-grad | Position |
| V-JEPA 2-AC | State plus action | Frozen V-JEPA 2 | Frozen encoder | Action sequence |
| VL-JEPA | Image or video vs text | Frozen text encoder | Asymmetry + frozen $Y$ branch | Text query |
| C-JEPA | Image patch blocks | EMA of $\theta$ | VICReg (variance + covariance) | Target block position |
| A-JEPA | Spectrogram patches | EMA of $\theta$ | EMA + stop-grad | Time-frequency position |
| LeJEPA | Same as I / V-JEPA | Shared $\theta$, no EMA | SIGReg toward $\mathcal{N}(0, I_d)$ | Target position |
| LLM-JEPA | Paired text views | Shared $\theta$ (the LLM) | Stop-grad + NTP co-training | View identity |

The core bet, in one line: **predict in representation space, not input space.**

## 4. I-JEPA: Images

**Paper:** *Self-supervised Learning from Images with a Joint-Embedding Predictive Architecture*, Assran et al., CVPR 2023
**Code:** `https://github.com/facebookresearch/ijepa`

### 4.1 Formalism

Image $x \in \mathbb{R}^{H \times W \times 3}$ is tokenized into $N$ patches $\{p_i\}_{i=1}^{N}$. Sample one context block $B_c \subset [N]$ and $M$ target blocks $\{B_{t,m}\}_{m=1}^{M}$.

$$
s_c = f_\theta\!\left(\{p_i : i \in B_c\}\right),
\qquad
s_{t,m} = f_{\bar\theta}\!\left(\{p_i : i \in B_{t,m}\}\right)
$$

The predictor is conditioned on positional mask tokens $\mathbf{m}_{t,m}$ for each target block:

$$
\hat{s}_{t,m} = g_\phi\!\left(s_c,\, \mathbf{m}_{t,m}\right)
$$

$$
\mathcal{L}_{\text{I-JEPA}}
= \frac{1}{M}\sum_{m=1}^{M}
\left\| \hat{s}_{t,m} - \mathrm{sg}\!\left[s_{t,m}\right] \right\|_2^2
$$

### 4.2 Multi-block masking

```
+---------------------------------------------------------------------+
|                    I-JEPA MASKING (224x224, patch 16)               |
|                                                                     |
|  Patch grid: 14 x 14 = 196 patches                                  |
|                                                                     |
|  +---+---+---+---+---+---+                                          |
|  |   |   |   |   |   |   |    T1..T4 = target blocks                |
|  +---+---+---+---+---+---+    each 15-20% of the image              |
|  |   |T1 |T1 |   |   |   |                                          |
|  +---+---+---+---+---+---+    Context = a large block               |
|  |   |T1 |T1 |T2 |T2 |   |    (85-100% coverage) minus every        |
|  +---+---+---+---+---+---+    patch belonging to a target           |
|  |   |   |T3 |T3 |T2 |   |                                          |
|  +---+---+---+---+---+---+    Effective masking: roughly 75-90%     |
|  |T4 |T4 |T3 |T3 |   |   |                                          |
|  +---+---+---+---+---+---+                                          |
|  |T4 |T4 |   |   |   |   |                                          |
|  +---+---+---+---+---+---+                                          |
+---------------------------------------------------------------------+
```

```python
def generate_ijepa_masks(image_size=224, patch_size=16, num_targets=4):
    """
    I-JEPA multi-block masking, single sample.

    Returns:
        context_mask: bool[num_patches]      True = visible to context encoder
        target_masks: list of bool[num_patches]
    """
    grid_size = image_size // patch_size          # 14
    num_patches = grid_size ** 2                  # 196

    target_masks = []
    all_target_patches = set()

    for _ in range(num_targets):
        block_h = random.randint(int(0.15 * grid_size), int(0.20 * grid_size))
        block_w = random.randint(int(0.15 * grid_size), int(0.20 * grid_size))

        start_h = random.randint(0, grid_size - block_h)
        start_w = random.randint(0, grid_size - block_w)

        mask = np.zeros((grid_size, grid_size), dtype=bool)
        mask[start_h:start_h + block_h, start_w:start_w + block_w] = True
        target_masks.append(mask.flatten())

        for h in range(start_h, start_h + block_h):
            for w in range(start_w, start_w + block_w):
                all_target_patches.add(h * grid_size + w)

    context_mask = np.ones(num_patches, dtype=bool)
    for idx in all_target_patches:
        context_mask[idx] = False

    return context_mask, target_masks
```

Note on overlap: the reference implementation samples target blocks independently, so blocks *may* overlap; the formal presentation is often stated with non-overlapping blocks for clarity. What matters for correctness is that the context excludes the union of all target patches, so no target patch is ever visible to the context encoder. See [Section 18](#18-source-conflicts-and-caveats).

### 4.3 Design choices that carry the method

**No hand-crafted augmentations.** Unlike DINO, SimCLR, and BYOL, there is no color jitter, blur, solarization, or multi-crop. Only random resized crop, for throughput. Masking alone drives representation learning, which avoids baking human invariance priors into the features.

**Asymmetry everywhere.** The context encoder sees a fraction of the patches; the target encoder sees each target block; the predictor is narrower than either. Example configuration: ViT-H encoder at width 1280 with a predictor at width 384.

**Efficiency.** One view instead of two, and the encoder never processes masked positions, giving roughly 5x fewer GPU-hours than MAE at comparable linear-probe quality.

## 5. V-JEPA: Video

**Paper:** *Revisiting Feature Prediction for Learning Visual Representations from Video*, Bardes et al., 2024 (released February 2024)

### 5.1 Formalism

Video $x \in \mathbb{R}^{T \times H \times W \times 3}$ is tokenized into spatio-temporal patches (tubelets) indexed by $(t, i, j)$, typically $16 \times 16$ spatial by 2 frames temporal. With context and target tubelet index sets $B_c$ and $B_t$:

$$
\mathcal{L}_{\text{V-JEPA}}
= \left\| g_\phi\!\left(f_\theta(x_{B_c}),\, \mathbf{m}_{B_t}\right)
- \mathrm{sg}\!\left[f_{\bar\theta}(x_{B_t})\right] \right\|_2^2
$$

Masks are sampled to span time, mixing short-range and long-range temporal extents so the model must learn both fast and slow dynamics. The released implementation optimizes an L1 objective in place of L2.

### 5.2 Spatiotemporal masking

```
+---------------------------------------------------------------------+
|                    V-JEPA MASKING                                   |
|                                                                     |
|  Frame 1      Frame 2      Frame 3      Frame 4                     |
|  +-------+    +-------+    +-------+    +-------+                   |
|  |.......|    |.......|    |.......|    |.......|                   |
|  |..###..|    |..###..|    |..###..|    |..###..|   <- SAME mask    |
|  |..###..|    |..###..|    |..###..|    |..###..|                   |
|  |.......|    |.......|    |.......|    |.......|                   |
|  +-------+    +-------+    +-------+    +-------+                   |
|                                                                     |
|  . = context (visible)          # = target (masked)                 |
|                                                                     |
|  The same spatial mask is applied to every frame in the clip.       |
+---------------------------------------------------------------------+
```

### 5.3 Why the spatial mask must be shared across frames

```
+---------------------------------------------------------------------+
|  BROKEN: independent mask per frame                                 |
|                                                                     |
|  Frame 1        Frame 2        Model's move                         |
|  +-------+      +-------+      +-------------+                      |
|  |[obj]  |      | ###   |      | copy the    |                      |
|  |   ### | -->  |[obj]  | -->  | patch from  |  <- TRIVIAL          |
|  |       |      |       |      | frame 1     |                      |
|  +-------+      +-------+      +-------------+                      |
|                                                                     |
|  The target content is visible in a neighbouring frame, so the      |
|  task reduces to patch copying. No dynamics are learned.            |
|                                                                     |
|---------------------------------------------------------------------|
|  CORRECT: one spatial mask shared by all frames                     |
|                                                                     |
|  Frame 1        Frame 2        Model's move                         |
|  +-------+      +-------+      +-------------+                      |
|  |[obj]##|      |[obj]##|      | infer motion|                      |
|  |    ###| -->  |    ###| -->  | and object  |  <- MEANINGFUL       |
|  |       |      |       |      | dynamics    |                      |
|  +-------+      +-------+      +-------------+                      |
|                                                                     |
|  The masked spatial region is never revealed at any timestep, so    |
|  the model must model motion and object permanence.                 |
+---------------------------------------------------------------------+
```

```python
def generate_vjepa_masks(num_frames, grid_h, grid_w, num_targets=8):
    """
    V-JEPA spatiotemporal masking, single sample.

    The same spatial footprint is removed from every frame of the
    context so that no target region is visible at any timestep.
    """
    target_masks = []
    all_masked_spatial = set()

    for _ in range(num_targets):
        block_h = random.randint(int(0.10 * grid_h), int(0.25 * grid_h))
        block_w = random.randint(int(0.10 * grid_w), int(0.25 * grid_w))
        start_h = random.randint(0, grid_h - block_h)
        start_w = random.randint(0, grid_w - block_w)

        # temporal extent varies per block: short and long range
        start_t = random.randint(0, num_frames - 2)
        end_t = random.randint(start_t + 1, num_frames)

        mask = np.zeros((num_frames, grid_h, grid_w), dtype=bool)
        mask[start_t:end_t,
             start_h:start_h + block_h,
             start_w:start_w + block_w] = True
        target_masks.append(mask)

        for h in range(start_h, start_h + block_h):
            for w in range(start_w, start_w + block_w):
                all_masked_spatial.add((h, w))

    context_mask = np.ones((num_frames, grid_h, grid_w), dtype=bool)
    for (h, w) in all_masked_spatial:
        context_mask[:, h, w] = False      # removed from ALL frames

    return context_mask, target_masks
```

### 5.5 I-JEPA versus V-JEPA

| Aspect | I-JEPA | V-JEPA |
|---|---|---|
| Input | Single image | Video clip |
| Tokens | 2D patches, 16 x 16 | 3D tubelets, 16 x 16 x 2 |
| Masking | Random blocks in 2D | Shared spatial footprint across frames, varied temporal extent |
| Target blocks | 4 | 8 |
| Temporal modelling | None | Implicit, forced by the masking rule |
| Loss | L2 | L1 |

## 6. V-JEPA 2 and V-JEPA 2-AC

**Paper:** *V-JEPA 2: Self-Supervised Video Models Enable Understanding, Prediction and Planning*, Assran et al., arXiv 2506.09985, June 2025

### 6.1 3D Rotary Position Embeddings

```
+---------------------------------------------------------------------+
|                      V-JEPA 2: 3D-RoPE                              |
|                                                                     |
|  Standard RoPE (1D):                                                |
|    q'_i = R(i) . q_i     rotation indexed by sequence position      |
|                                                                     |
|  3D-RoPE:                                                           |
|    rotations applied in disjoint 2D subspaces of the embedding,      |
|    one group per axis: height, width, time                          |
|                                                                     |
|    for a token at (h, w, t):                                        |
|        q'_(h,w,t) = R_h(h) . R_w(w) . R_t(t) . q_(h,w,t)            |
|                                                                     |
|    each R is block-diagonal and acts on its own subspace, so the    |
|    three axes do not interfere                                      |
|                                                                     |
|  Benefits:                                                          |
|  * one scheme for space and time, no learned absolute table         |
|  * extrapolates to longer clips and higher resolution               |
|  * relative offsets in time are directly encoded, which helps       |
|    temporal reasoning                                               |
+---------------------------------------------------------------------+
```

### 6.2 Scale and configuration

```yaml

  hidden_dim: 1664
  num_heads: 16
  num_layers: 48

  source: internet video

training:
  stage1:
    objective: masked latent prediction
    epochs: 100
  stage2:                          # produces V-JEPA 2-AC

    data: robot interaction video (Droid), ~62 hours
```

### 6.3 V-JEPA 2-AC: the action-conditioned world model

Given a state embedding $s_t$ and an action $a_t$:

$$
\hat{s}_{t+1} = g_\phi\!\left(s_t,\, a_t\right),
\qquad
\mathcal{L} = \left\| \hat{s}_{t+1} - \mathrm{sg}\!\left[f_{\bar\theta}(x_{t+1})\right] \right\|_2^2
$$

```
+---------------------------------------------------------------------+
|                    V-JEPA 2-AC ARCHITECTURE                         |
|                                                                     |
|  Visual states                 Actions                              |
|  [s_0, s_1, ..., s_T]          [a_0, a_1, ..., a_(T-1)]             |
|         |                            |                              |
|         v                            v                              |
|  +--------------+             +--------------+                      |
|  | V-JEPA 2     |             | Action       |                      |
|  | encoder      |             | encoder      |                      |
|  | (FROZEN)     |             | (MLP)        |                      |
|  +------+-------+             +------+-------+                      |
|         |                            |                              |
|         +-------------+--------------+                              |
|                       v                                             |
|              +------------------+                                   |
|              | concatenate      |                                   |
|              | [v_i ; a_i]      |                                   |
|              +--------+---------+                                   |
|                       v                                             |
|              +--------------------------+                           |
|              | action-conditioned       |                           |
|              | predictor                |                           |
|              | (block-causal attention) |                           |
|              +--------+-----------------+                           |
|                       v                                             |
|         predicted future states                                     |
|         [s_hat_(T+1), ..., s_hat_(T+K)]                             |
|                                                                     |
|  Two training signals:                                              |
|  1. Teacher forcing: predict s_(t+1) from true s_(0:t), a_(0:t)     |
```

The visual encoder stays frozen in this stage. That is what preserves the general world knowledge learned from a million hours of video while only 62 hours of robot data shape the dynamics head.

### 6.4 Planning: MPC with the cross-entropy method

```
+---------------------------------------------------------------------+
|                    MPC + CEM PLANNING LOOP                          |
|                                                                     |
|  Goal: find an action sequence that drives the latent state toward   |
|  a goal image embedding s_goal                                      |
|                                                                     |
|  1. Sample N candidate action sequences a^(1..N) ~ N(mu, sigma)      |
|                                                                     |
|  2. Roll out V-JEPA 2-AC for each candidate:                        |
|       s_0 -[a]-> s_hat_1 -[a]-> s_hat_2 -> ... -> s_hat_H           |
|                                                                     |
|  3. Score each trajectory:                                          |
|       score(a) = - || s_hat_H - s_goal ||^2                         |
|                                                                     |
|  4. Keep the top-K elites                                           |
|                                                                     |
|  5. Refit the sampling distribution to the elites:                   |
|       mu    <- mean(elite actions)                                  |
|       sigma <- std(elite actions)                                   |
|                                                                     |
|  6. Repeat 1-5 for M iterations                                     |
|                                                                     |
|  7. Execute only the first action of the best sequence, then         |
|     re-plan from the new observation (receding horizon)              |
|                                                                     |
|  No reward model, no task-specific training, no demonstrations.      |
+---------------------------------------------------------------------+
```

## 7. VL-JEPA: Vision-Language

**Paper:** *VL-JEPA: Joint Embedding Predictive Architecture for Vision-Language*, Chen et al., 2025

### 7.1 Formalism

Two encoders and one predictor:

- $X$-encoder $f_\theta^X$: visual input $v \mapsto s^X \in \mathbb{R}^d$
- $Y$-encoder $f_{\bar\theta}^Y$: text $y \mapsto s^Y \in \mathbb{R}^d$, usually a frozen pretrained sentence embedder
- Predictor $g_\phi$ mapping visual embeddings into the text embedding space

$$
\hat{s}^Y = g_\phi\!\left(s^X\right),
\qquad
\mathcal{L}_{\text{VL-JEPA}}
= \left\| g_\phi\!\left(f_\theta^X(v)\right) - \mathrm{sg}\!\left[f_{\bar\theta}^Y(y)\right] \right\|_2^2
$$

The target branch is frozen rather than EMA-tracked, which is itself the anti-collapse mechanism: a fixed, non-degenerate target distribution cannot be gamed.

### 7.2 Contrast with autoregressive VLMs

```
+---------------------------------------------------------------------+
|  TRADITIONAL VLM (LLaVA-style)                                      |
|                                                                     |
|  Image ---> vision encoder ---> projector ---> [LLM token stream]   |
|  Text  ------------------------------------->  [LLM token stream]   |
|                                                       |             |
|                                                       v             |
|                                        +----------------------+     |
|                                        | autoregressive LLM   |     |
|                                        | decoder, next-token  |     |
|                                        +----------+-----------+     |
|                                                   v                 |
|                                    token-by-token generation for    |
|                                    every query, even yes/no ones    |
|---------------------------------------------------------------------|
|  VL-JEPA                                                            |
|                                                                     |
|  Image/Video ---> V-JEPA 2 encoder (frozen) ---+                    |
|                                                v                    |
|  Text query  ---> text encoder ---------> +-----------+             |
|                                           | predictor |             |
|                                           +-----+-----+             |
|                                                 v                   |
|                              predicted CONTINUOUS text embedding    |
|                                                 |                   |
|              +----------------+-----------------+---------------+    |
|              v                v                                v    |
|         retrieval        classification              optional text   |
|      (cosine search)   (nearest class emb)             decoder       |
+---------------------------------------------------------------------+
```

### 7.3 Components

1. **Vision encoder,** a frozen V-JEPA 2. Freezing preserves the video world model and keeps trainable parameter count low.
2. **Text encoder,** e.g. SONAR or a sentence-transformer. Optionally trainable.
3. **Vision-language predictor,** a small cross-attention transformer (order of 6 layers) that maps visual embeddings, conditioned on the query, into text embedding space.
4. **Optional lightweight text decoder,** invoked only when natural-language output is actually required.

### 7.4 Selective decoding


## 8. C-JEPA: Contrastive Regularized JEPA

**Paper:** *Connecting Joint-Embedding Predictive Architecture with Contrastive Self-Supervised Learning*, Tong et al., arXiv 2410.19560

### 8.1 Motivation

EMA plus stop-gradient prevents *total* collapse in practice but does not guarantee that the embedding space stays well-conditioned. I-JEPA runs can still drift toward low effective rank, where many dimensions are near-constant or strongly correlated. C-JEPA adds the explicit VICReg regularizer so that non-degeneracy is enforced rather than hoped for.

### 8.2 The VICReg terms

```
+---------------------------------------------------------------------+
|                    C-JEPA = I-JEPA + VICReg                         |
|                                                                     |
|  1. VARIANCE (prevents constant / dimensional collapse)             |
|       L_var = mean_j max(0, gamma - sqrt(Var(z_j) + eps))           |
|     every dimension is pushed to have std at least gamma            |
|                                                                     |
|  2. INVARIANCE (alignment; in JEPA this is the prediction term)     |
|       L_inv = || z_1 - z_2 ||^2                                     |
|                                                                     |
|  3. COVARIANCE (decorrelation)                                      |
|       L_cov = (1/d) * sum_(i != j) Cov(z_i, z_j)^2                  |
|     off-diagonal covariance is driven to zero, so dimensions carry  |
|     distinct information                                            |
|                                                                     |
|  Total:                                                             |
|       L = L_pred + lambda_var * L_var + lambda_cov * L_cov          |
|       lambda_var ~ 25,  lambda_cov ~ 25,  gamma = 1                 |
+---------------------------------------------------------------------+
```

$$
\mathcal{L}_{\text{C-JEPA}}
= \mathcal{L}_{\text{I-JEPA}}
+ \lambda_v \sum_{j=1}^{d} \max\!\left(0,\ \gamma - \sqrt{\mathrm{Var}(z_j) + \epsilon}\right)
+ \lambda_c \frac{1}{d} \sum_{i \neq j} \left[\mathrm{Cov}(z)_{ij}\right]^2
$$

### 8.3 Implementation

```python
def off_diagonal(m):
    n = m.shape[0]
    return m[~keras.ops.eye(n, dtype="bool")]


def vicreg_loss(z1, z2, lambda_var=25.0, lambda_cov=25.0,
                gamma=1.0, eps=1e-4):
    """
    VICReg regularization.

    z1, z2: [B, D] embedding batches (in C-JEPA: predicted and target)
    """
    # invariance
    inv_loss = keras.ops.mean((z1 - z2) ** 2)

    # variance: penalise any dimension whose std falls below gamma
    std_z1 = keras.ops.sqrt(keras.ops.var(z1, axis=0) + eps)
    std_z2 = keras.ops.sqrt(keras.ops.var(z2, axis=0) + eps)
    var_loss = keras.ops.mean(keras.ops.relu(gamma - std_z1))
    var_loss += keras.ops.mean(keras.ops.relu(gamma - std_z2))

    # covariance: decorrelate dimensions
    z1c = z1 - keras.ops.mean(z1, axis=0)
    z2c = z2 - keras.ops.mean(z2, axis=0)
    batch = keras.ops.shape(z1)[0]
    d = keras.ops.shape(z1)[1]

    cov_z1 = keras.ops.matmul(keras.ops.transpose(z1c), z1c) / (batch - 1)
    cov_z2 = keras.ops.matmul(keras.ops.transpose(z2c), z2c) / (batch - 1)

    cov_loss = keras.ops.sum(off_diagonal(cov_z1) ** 2) / d
    cov_loss += keras.ops.sum(off_diagonal(cov_z2) ** 2) / d

    return inv_loss + lambda_var * var_loss + lambda_cov * cov_loss


def cjepa_loss(predicted_emb, target_emb, lambda_var=25.0, lambda_cov=25.0):
    pred_loss = keras.ops.mean((predicted_emb - target_emb) ** 2)
    reg = vicreg_loss(predicted_emb, target_emb, lambda_var, lambda_cov)
    return pred_loss + reg
```

Practical caution: the variance and covariance statistics are computed *per batch*, so C-JEPA is sensitive to small batches and to gradient accumulation schemes that shrink the effective statistical batch.

### 8.4 I-JEPA versus C-JEPA

| Aspect | I-JEPA | C-JEPA |
|---|---|---|
| Collapse prevention | Implicit: EMA, stop-grad, bottleneck | Explicit: variance and covariance terms |
| Feature conditioning | Dimensions may correlate | Decorrelated by construction |
| Training stability | Good | Better, at the cost of batch sensitivity |
| ImageNet linear probe (ViT-H) | 81.5% | 82.8% |
| Extra hyperparameters | None | $\lambda_v$, $\lambda_c$, $\gamma$ |

## 10. LeJEPA: Latent-Euclidean JEPA

LeJEPA strips out the heuristic scaffolding: no EMA teacher, no stop-gradient asymmetry, no predictor bottleneck tricks. A single principled regularizer replaces all of it.

### 10.1 Shared encoder, no EMA

$$
s_c = f_\theta(x_c), \qquad s_t = f_\theta(x_t)
$$

Both branches use the *same* parameters $\theta$.

### 10.2 Prediction loss

$$
\mathcal{L}_{\text{pred}} = \left\| g_\phi(s_c,\, z) - s_t \right\|_2^2
$$

### 10.3 SIGReg: Sketched Isotropic Gaussian Regularization

The target distribution for embeddings is the isotropic Gaussian $\mathcal{N}(0, I_d)$. Testing $d$-dimensional Gaussianity directly is impractical, so SIGReg *sketches* it with random 1D projections.

Draw $K$ directions $\{u_k\}_{k=1}^{K} \sim \mathrm{Unif}(\mathbb{S}^{d-1})$. For a batch of embeddings $\{s_i\}_{i=1}^{B}$, project:

$$
\pi_k = \left\{ u_k^\top s_i \right\}_{i=1}^{B}
$$

If $s \sim \mathcal{N}(0, I_d)$ then every projection satisfies $\pi_k \sim \mathcal{N}(0, 1)$. Compare the empirical CDF $\hat F_{\pi_k}$ against the standard normal CDF $\Phi$ under a distributional distance $D$ (1D Wasserstein, energy distance, or Cramer-von Mises):

$$
\mathcal{L}_{\text{SIGReg}} = \frac{1}{K}\sum_{k=1}^{K} D\!\left(\hat F_{\pi_k},\ \Phi\right)
$$

### 10.4 Total objective

$$
\mathcal{L}_{\text{LeJEPA}} = \mathcal{L}_{\text{pred}} + \lambda\, \mathcal{L}_{\text{SIGReg}}
$$

One hyperparameter, $\lambda$. Collapse is provably excluded because $\mathcal{N}(0, I_d)$ is non-degenerate in every direction: a collapsed or low-rank embedding produces at least one projection whose empirical distribution is far from $\Phi$, which the regularizer penalizes.

### 10.5 Why this matters practically

| Removed | Replaced by | Consequence |
|---|---|---|
| EMA teacher | Shared encoder | One weight copy, no $\tau$ schedule to tune |
| Stop-gradient asymmetry | Shared encoder | Gradients flow through both branches |
| Predictor bottleneck heuristic | SIGReg | Predictor capacity is a free design choice |
| Multiple anti-collapse knobs | Single $\lambda$ | Far smaller hyperparameter search |

Cost: the 1D projections are cheap, but $K$ must be large enough to cover the sphere well, and the distributional distance is a batch statistic, so LeJEPA inherits C-JEPA's sensitivity to effective batch size.

## 11. LLM-JEPA: Text and Multi-View Language

LLM-JEPA adds a JEPA term to standard language-model training using **multiple views of the same knowledge**, for example a natural-language problem statement $x^{\text{NL}}$ and a code solution $x^{\text{CODE}}$ that are semantically equivalent but lexically unrelated.

### 11.1 Next-token prediction term

$$
\mathcal{L}_{\text{NTP}}(\theta) = -\sum_{t=1}^{T} \log p_\theta\!\left(x_t \mid x_{<t}\right)
$$

### 11.2 JEPA term

Let $h_\theta(x) \in \mathbb{R}^d$ be a pooled hidden state from the LLM, e.g. the last-token hidden state at a designated layer. For a paired view $(x^a, x^b)$:

$$
s^a = h_\theta(x^a), \qquad s^b = h_\theta(x^b)
$$

$$
\mathcal{L}_{\text{JEPA}}^{\text{LLM}} = \left\| g_\phi(s^a) - \mathrm{sg}\!\left[s^b\right] \right\|_2^2
$$

### 11.3 Combined objective

$$
\mathcal{L}_{\text{LLM-JEPA}} = \mathcal{L}_{\text{NTP}} + \alpha\, \mathcal{L}_{\text{JEPA}}^{\text{LLM}},
\qquad \alpha \approx 0.1
$$

### 11.4 Cost structure

- **Training:** two extra forward passes per paired sample, one per view, plus a small predictor head.
- **Inference:** identical to a standard LLM. The JEPA head is discarded and only $p_\theta(x_t \mid x_{<t})$ is used, so there is no serving-time penalty.

### 11.5 Why it works

NTP supervises surface tokens only. The JEPA term pulls together the hidden states of inputs that are semantically equivalent but surface-different, regularizing the representation toward meaning rather than form. The two objectives are complementary: NTP keeps the model generative and fluent, the JEPA term shapes the latent space it generates from.

## 12. H-JEPA: Hierarchical Planning

H-JEPA is the architectural target of LeCun's programme rather than a single released model. Multiple JEPAs are stacked so that each level predicts at a coarser time scale and higher abstraction than the one below it.

```
+---------------------------------------------------------------------+
|                    H-JEPA (conceptual)                              |
|                                                                     |
|  Level 3   abstract, long horizon                                   |
|    "cross the road"                                                 |
|    s3_t ---predict---> s3_(t+1)          (seconds to minutes)       |
|      ^                                                              |
|      | abstraction                                                  |
|  Level 2                                                            |
|    "take a step"                                                    |
|    s2_t ---predict---> s2_(t+1)          (hundreds of ms)           |
|      ^                                                              |
|      |                                                              |
|  Level 1   concrete, short horizon                                  |
|    "contract the quadriceps"                                        |
|    s1_t ---predict---> s1_(t+1)          (milliseconds)             |
|      ^                                                              |
|      |                                                              |
|  Raw observation stream                                             |
|                                                                     |
|  Planning: energy minimization proceeds top-down. A coarse plan is  |

|  search at each level stays short-horizon and tractable.            |
+---------------------------------------------------------------------+
```

The practical bridge from today's models: V-JEPA 2-AC is a single-level instance of this idea, with MPC and CEM standing in for energy minimization at one time scale. The unsolved part is learning the abstraction hierarchy itself rather than hand-specifying the levels.

## 13. Collapse: Theory and Prevention

### 13.1 Why collapse is the central risk

The trivial solution $f_\theta \equiv f_{\bar\theta} \equiv \text{const}$ drives the prediction loss to exactly zero. Nothing in the objective itself forbids it. In EBM terms, the model is free to flatten the energy surface everywhere instead of shaping it, because there are no contrastive samples pushing energy up on incompatible pairs. Every mechanism below exists to make the flat solution unreachable or unattractive.

### 13.2 Failure modes

```
+---------------------------------------------------------------------+
|                    COLLAPSE FAILURE MODES                           |
|                                                                     |
|  Mode 1: constant output                                            |
|    all inputs map to the same embedding; loss is trivially zero;     |
|    zero information retained                                        |
|                                                                     |
|  Mode 2: dimensional collapse                                       |
|    embeddings vary, but only across a few directions; most           |
|    dimensions are near-constant or duplicated; effective rank        |
|    far below d; downstream probes saturate early                     |
|                                                                     |
|  Mode 3: informational shortcut                                     |
|    encoder and predictor co-adapt so the prediction is made easy     |
|    without semantic content (leaked position, low-level statistics); |
|    training loss looks healthy, transfer is poor                     |
|                                                                     |
|  Diagnostics:                                                       |
|    * loss falling to near zero unusually fast -> mode 1             |
|    * singular value spectrum of the embedding matrix decaying        |
|      abruptly -> mode 2                                             |
|    * low loss with weak linear probe -> mode 3                      |
+---------------------------------------------------------------------+
```

### 13.3 The six mechanisms

```
+---------------------------------------------------------------------+
|                 COLLAPSE PREVENTION MECHANISMS                      |
|                                                                     |
|  1. EMA TARGET ENCODER                                              |
|     theta_bar <- tau * theta_bar + (1 - tau) * theta                |
|     tau typically 0.996 -> 0.9999, increasing during training       |
|     The teacher lags the student, so the student cannot chase a      |
|     target it is simultaneously defining. Stabilises the fixed point.|
|                                                                     |
|  2. STOP GRADIENT                                                   |
|     target_emb = stop_gradient(target_encoder(x))                   |
|     No gradient path exists for making the target easier to hit.     |
|     The target branch changes only through the EMA.                 |
|                                                                     |
|  3. ASYMMETRIC ARCHITECTURE (predictor bottleneck)                  |
|     predictor width and depth << encoder width and depth            |
|     e.g. ViT-H encoder at 1280 with a predictor at 384              |
|     A weak predictor cannot memorise or shortcut, so the burden of   |
|     being predictable falls on the encoder's representation.        |
|                                                                     |
|  4. HIGH MASKING RATIO                                              |
|     mask 75-90% of the input                                        |
|     Removes the copy-and-interpolate solution and forces the model   |
|     to use global structure.                                        |
|                                                                     |
|  5. EXPLICIT DISTRIBUTIONAL REGULARIZATION                          |
|     C-JEPA / VJ-VCR: variance term (each dimension keeps spread)     |
|                      covariance term (dimensions decorrelated)      |
|     LeJEPA:          SIGReg pushes embeddings toward N(0, I_d)       |
|     These attack modes 1 and 2 directly rather than structurally.    |
|                                                                     |
|  6. MULTI-BLOCK TARGETS                                             |
|     predict 4 to 8 diverse regions per sample                       |
|     Different positions demand different answers, which rules out    |
|     position-independent constant predictions and encourages         |
|     spatially aware features.                                       |
+---------------------------------------------------------------------+
```

### 13.4 EMA schedule

```python
def ema_schedule(step, total_steps, base_tau=0.996, final_tau=1.0):
    """
    Cosine ramp of the EMA coefficient.

    Early training: lower tau, the teacher tracks the student closely
                    so useful structure propagates quickly.
    Late training:  tau near 1.0, the teacher is nearly frozen and
                    provides very stable targets.
    """
    progress = step / total_steps
    return final_tau - (final_tau - base_tau) * (1 + math.cos(math.pi * progress)) / 2


def update_ema(context_encoder, target_encoder, tau):
    for p_ctx, p_tgt in zip(context_encoder.variables, target_encoder.variables):
        p_tgt.assign(tau * p_tgt + (1 - tau) * p_ctx)
```

### 13.5 Which mechanisms each variant relies on

| Variant | EMA | Stop-grad | Bottleneck | High mask | Explicit reg |
|---|---|---|---|---|---|
| I-JEPA | Yes | Yes | Yes | Yes | No |
| V-JEPA / V-JEPA 2 | Yes | Yes | Yes | Yes | No |
| V-JEPA 2-AC | Frozen encoder | Yes | Yes | n/a | No |
| VL-JEPA | Frozen text branch | Yes | Yes | n/a | No |
| C-JEPA | Yes | Yes | Yes | Yes | VICReg |
| A-JEPA | Yes | Yes | Yes | Yes | No |
| LeJEPA | No | No | Optional | Yes | SIGReg |
| LLM-JEPA | No | Yes | Yes | n/a | NTP co-training |

## 14. Training Procedures

### 14.1 Reference training loop

```python
class JEPATrainer:
    """General JEPA training framework."""

    def __init__(self, context_encoder, target_encoder, predictor,
                 optimizer, ema_decay_base=0.996, ema_decay_final=1.0):
        self.context_encoder = context_encoder
        self.target_encoder = target_encoder
        self.predictor = predictor
        self.optimizer = optimizer
        self.ema_decay_base = ema_decay_base
        self.ema_decay_final = ema_decay_final
        self._initialize_target_encoder()

    def _initialize_target_encoder(self):
        """Target starts as an exact copy of the context encoder."""
        for p_ctx, p_tgt in zip(self.context_encoder.trainable_variables,
                                self.target_encoder.variables):
            p_tgt.assign(p_ctx)

    def _get_ema_decay(self, step, total_steps):
        progress = step / total_steps
        return self.ema_decay_final - (
            self.ema_decay_final - self.ema_decay_base
        ) * (1 + math.cos(math.pi * progress)) / 2

    def _update_target_encoder(self, tau):
        for p_ctx, p_tgt in zip(self.context_encoder.trainable_variables,
                                self.target_encoder.variables):
            p_tgt.assign(tau * p_tgt + (1 - tau) * p_ctx)

    def train_step(self, batch, step, total_steps):
        with tf.GradientTape() as tape:
            context_mask, target_masks = self.generate_masks(batch)

            context_patches = self.apply_mask(batch, context_mask)
            target_patches = [self.apply_mask(batch, m) for m in target_masks]

            # student branch
            context_emb = self.context_encoder(context_patches, training=True)

            # teacher branch: EMA weights, inference mode, no gradient
            target_embs = []
            for t_patches in target_patches:
                t_emb = self.target_encoder(t_patches, training=False)
                target_embs.append(keras.ops.stop_gradient(t_emb))

            # one prediction per target block, conditioned on its position
            pred_embs = []
            for t_mask in target_masks:
                pos_tokens = self.get_position_tokens(t_mask)
                pred_embs.append(
                    self.predictor(context_emb, pos_tokens, training=True)
                )

            loss = 0.0
            for pred, target in zip(pred_embs, target_embs):
                loss += keras.ops.mean((pred - target) ** 2)
            loss /= len(pred_embs)

        trainable_vars = (self.context_encoder.trainable_variables
                          + self.predictor.trainable_variables)
        gradients = tape.gradient(loss, trainable_vars)
        self.optimizer.apply_gradients(zip(gradients, trainable_vars))

        # teacher update happens AFTER the student step
        self._update_target_encoder(self._get_ema_decay(step, total_steps))
        return loss
```

Ordering matters: initialize the teacher from the student, take the student step, then apply the EMA. Applying the EMA first makes the teacher a function of the current gradient step and weakens the asymmetry.

Keras 3 (backend-agnostic) reference components.

### 15.1 Transformer block

```python
import keras
from keras import ops


class TransformerBlock(keras.layers.Layer):
    """Standard pre-norm transformer block.

    :param embed_dim: embedding dimension
    :param num_heads: number of attention heads
    :param mlp_ratio: MLP expansion ratio
    :param dropout: dropout rate
    """

    def __init__(self, embed_dim: int, num_heads: int,
                 mlp_ratio: float = 4.0, dropout: float = 0.0, **kwargs):
        super().__init__(**kwargs)
        self.embed_dim = embed_dim
        self.num_heads = num_heads
        self.mlp_ratio = mlp_ratio
        self.dropout_rate = dropout

    def build(self, input_shape):
        self.norm1 = keras.layers.LayerNormalization(epsilon=1e-6)
        self.attn = keras.layers.MultiHeadAttention(
            num_heads=self.num_heads,
            key_dim=self.embed_dim // self.num_heads,
            dropout=self.dropout_rate,
        )
        self.norm2 = keras.layers.LayerNormalization(epsilon=1e-6)
        mlp_dim = int(self.embed_dim * self.mlp_ratio)
        self.mlp = keras.Sequential([
            keras.layers.Dense(mlp_dim, activation="gelu"),
            keras.layers.Dropout(self.dropout_rate),
            keras.layers.Dense(self.embed_dim),
            keras.layers.Dropout(self.dropout_rate),
        ])
        super().build(input_shape)

    def call(self, x, training=None):
        h = self.norm1(x)
        x = x + self.attn(h, h, training=training)
        x = x + self.mlp(self.norm2(x), training=training)
        return x
```

### 15.2 Encoder

```python
class JEPAEncoder(keras.layers.Layer):
    """JEPA context / target encoder (ViT trunk).

    Consumes patch embeddings and returns contextualised embeddings.
    The same class is instantiated twice: once trainable (context),
    once EMA-tracked and frozen (target).
    """

    def __init__(self, embed_dim: int = 768, num_heads: int = 12,
                 num_layers: int = 12, mlp_ratio: float = 4.0,
                 dropout: float = 0.0, **kwargs):
        super().__init__(**kwargs)
        self.embed_dim = embed_dim
        self.num_heads = num_heads
        self.num_layers = num_layers
        self.mlp_ratio = mlp_ratio
        self.dropout_rate = dropout

    def build(self, input_shape):
        self.blocks = [
            TransformerBlock(
                embed_dim=self.embed_dim,
                num_heads=self.num_heads,
                mlp_ratio=self.mlp_ratio,
                dropout=self.dropout_rate,
                name=f"block_{i}",
            )
            for i in range(self.num_layers)
        ]
        self.norm = keras.layers.LayerNormalization(epsilon=1e-6, name="norm")
        super().build(input_shape)

    def call(self, x, training=None):
        """x: [B, N, D] -> [B, N, D]"""
        for block in self.blocks:
            x = block(x, training=training)
        return self.norm(x)
```

### 15.3 Predictor

```python
class JEPAPredictor(keras.layers.Layer):
    """JEPA predictor.

    Maps context embeddings plus target position information to
    predicted target embeddings. Deliberately narrower than the
    encoder: predictor_dim is roughly 0.3-0.5 x embed_dim.
    """

    def __init__(self, embed_dim: int = 768, predictor_dim: int = 384,
                 num_heads: int = 6, num_layers: int = 6,
                 num_positions: int = 196, **kwargs):
        super().__init__(**kwargs)
        self.embed_dim = embed_dim
        self.predictor_dim = predictor_dim
        self.num_heads = num_heads
        self.num_layers = num_layers
        self.num_positions = num_positions

    def build(self, input_shape):
        self.input_proj = keras.layers.Dense(self.predictor_dim,
                                             name="input_proj")

        # single learned token standing in for "unknown content here"
        self.mask_token = self.add_weight(
            name="mask_token",
            shape=(1, 1, self.predictor_dim),
            initializer="glorot_uniform",
            trainable=True,
        )

        # positional table; for video use 3D-RoPE instead of this
        self.pos_embed = self.add_weight(
            name="pos_embed",
            shape=(1, self.num_positions, self.predictor_dim),
            initializer="glorot_uniform",
            trainable=True,
        )

        self.blocks = [
            TransformerBlock(
                embed_dim=self.predictor_dim,
                num_heads=self.num_heads,
                mlp_ratio=4.0,
                name=f"pred_block_{i}",
            )
            for i in range(self.num_layers)
        ]
        self.norm = keras.layers.LayerNormalization(epsilon=1e-6,
                                                   name="pred_norm")
        self.output_proj = keras.layers.Dense(self.embed_dim,
                                              name="output_proj")
        super().build(input_shape)

    def call(self, context_emb, target_positions, training=None):
        """
        :param context_emb: [B, N_ctx, embed_dim]
        :param target_positions: [B, N_tgt] integer position indices
        :return: [B, N_tgt, embed_dim]
        """
        batch_size = ops.shape(context_emb)[0]
        num_targets = ops.shape(target_positions)[1]

        context = self.input_proj(context_emb)

        mask_tokens = ops.tile(self.mask_token, [batch_size, num_targets, 1])
        target_pos_emb = ops.take(self.pos_embed[0], target_positions, axis=0)
        mask_tokens = mask_tokens + target_pos_emb

        x = ops.concatenate([context, mask_tokens], axis=1)
        for block in self.blocks:
            x = block(x, training=training)
        x = self.norm(x)

        predictions = x[:, -num_targets:, :]
        return self.output_proj(predictions)
```

### 15.4 Full model

```python
class JEPA(keras.Model):
    """Joint Embedding Predictive Architecture.

    Bundles the trainable context encoder, the EMA target encoder,
    and the predictor.
    """

    def __init__(self, encoder_config: dict, predictor_config: dict,
                 ema_decay: float = 0.996, **kwargs):
        super().__init__(**kwargs)
        self.ema_decay = ema_decay

        self.context_encoder = JEPAEncoder(**encoder_config,
                                           name="context_encoder")
        self.target_encoder = JEPAEncoder(**encoder_config,
                                          name="target_encoder")
        self.target_encoder.trainable = False

        self.predictor = JEPAPredictor(**predictor_config, name="predictor")

    def build(self, input_shape):
        super().build(input_shape)
        self._copy_weights_to_target()

    def _copy_weights_to_target(self):
        for ctx_var, tgt_var in zip(self.context_encoder.trainable_variables,
                                    self.target_encoder.variables):
            tgt_var.assign(ctx_var)

    def update_target_encoder(self, tau=None):
        tau = self.ema_decay if tau is None else tau
        for ctx_var, tgt_var in zip(self.context_encoder.trainable_variables,
                                    self.target_encoder.variables):
            tgt_var.assign(tau * tgt_var + (1 - tau) * ctx_var)

    def call(self, inputs, training=None):
        """Inference path: context encoder only, for feature extraction."""
        return self.context_encoder(inputs, training=training)

    def compute_loss(self, context_patches, target_patches,
                     target_positions, training=True):
        context_emb = self.context_encoder(context_patches, training=training)

        target_emb = self.target_encoder(target_patches, training=False)
        target_emb = ops.stop_gradient(target_emb)

        pred_emb = self.predictor(context_emb, target_positions,
                                  training=training)
        return ops.mean((pred_emb - target_emb) ** 2)

    def get_config(self):
        config = super().get_config()
        config.update({"ema_decay": self.ema_decay})
        return config
```

### 15.5 Batched mask generation

```python
def generate_ijepa_masks_batch(
    batch_size: int,
    num_patches: int,
    num_targets: int = 4,
    target_scale: tuple = (0.15, 0.2),
    target_aspect_ratio: tuple = (0.75, 1.5),
):
    """
    Batched I-JEPA masks.

    :return: (context_masks, target_masks_list, target_positions_list)
    """
    grid_size = int(num_patches ** 0.5)

    context_masks, target_masks_list, target_positions_list = [], [], []

    for _ in range(batch_size):
        all_target_positions = set()
        sample_target_masks = []

        for _ in range(num_targets):
            scale = np.random.uniform(*target_scale)
            aspect = np.random.uniform(*target_aspect_ratio)

            block_area = int(num_patches * scale)
            block_h = max(1, int(np.sqrt(block_area / aspect)))
            block_w = max(1, int(block_area / block_h))
            block_h = min(block_h, grid_size)
            block_w = min(block_w, grid_size)

            start_h = np.random.randint(0, grid_size - block_h + 1)
            start_w = np.random.randint(0, grid_size - block_w + 1)

            mask = np.zeros((grid_size, grid_size), dtype=bool)
            mask[start_h:start_h + block_h, start_w:start_w + block_w] = True
            sample_target_masks.append(mask.flatten())

            for h in range(start_h, start_h + block_h):
                for w in range(start_w, start_w + block_w):
                    all_target_positions.add(h * grid_size + w)

        context_mask = np.ones(num_patches, dtype=bool)
        for pos in all_target_positions:
            context_mask[pos] = False

        context_masks.append(context_mask)
        target_masks_list.append(sample_target_masks)
        target_positions_list.append(sorted(all_target_positions))

    return context_masks, target_masks_list, target_positions_list


def generate_vjepa_masks_batch(
    batch_size: int,
    num_frames: int,
    grid_h: int,
    grid_w: int,
    num_targets: int = 8,
    spatial_scale: tuple = (0.1, 0.25),
):
    """
    Batched V-JEPA spatiotemporal masks.

    Invariant: the spatial footprint of every target is removed from
    the context in ALL frames.
    """
    context_masks, target_masks_list = [], []

    for _ in range(batch_size):
        masked_spatial = set()
        sample_targets = []

        for _ in range(num_targets):
            scale = np.random.uniform(*spatial_scale)
            block_h = max(1, int(grid_h * np.sqrt(scale)))
            block_w = max(1, int(grid_w * np.sqrt(scale)))

            start_h = np.random.randint(0, max(1, grid_h - block_h))
            start_w = np.random.randint(0, max(1, grid_w - block_w))

            start_t = np.random.randint(0, num_frames)
            end_t = np.random.randint(start_t + 1, num_frames + 1)

            mask = np.zeros((num_frames, grid_h, grid_w), dtype=bool)
            mask[start_t:end_t,
                 start_h:start_h + block_h,
                 start_w:start_w + block_w] = True
            sample_targets.append(mask)

            for h in range(start_h, start_h + block_h):
                for w in range(start_w, start_w + block_w):
                    masked_spatial.add((h, w))

        context_mask = np.ones((num_frames, grid_h, grid_w), dtype=bool)
        for (h, w) in masked_spatial:
            context_mask[:, h, w] = False

        context_masks.append(context_mask)
        target_masks_list.append(sample_targets)

    return context_masks, target_masks_list
```

### 15.6 SIGReg (LeJEPA) sketch

```python
def sigreg_loss(embeddings, num_directions=64, eps=1e-6):
    """
    Sketched Isotropic Gaussian Regularization.

    Projects the batch onto random unit directions and penalises the
    1D distance between each empirical projection and N(0, 1).

    :param embeddings: [B, D]
    :return: scalar loss
    """
    b = ops.shape(embeddings)[0]
    d = ops.shape(embeddings)[1]

    # random directions on the unit sphere
    u = keras.random.normal((d, num_directions))
    u = u / (ops.sqrt(ops.sum(u ** 2, axis=0, keepdims=True)) + eps)

    proj = ops.matmul(embeddings, u)                  # [B, K]

    # sorted projections give the empirical quantile function
    proj_sorted = ops.sort(proj, axis=0)

    # standard normal quantiles at plotting positions (i - 0.5) / B
    positions = (ops.arange(1, b + 1, dtype="float32") - 0.5) / ops.cast(b, "float32")
    normal_q = normal_ppf(positions)                  # [B]
    normal_q = ops.expand_dims(normal_q, axis=-1)     # [B, 1]

    # 1D Wasserstein-2 between empirical and standard normal
    return ops.mean((proj_sorted - normal_q) ** 2)
```

`normal_ppf` is the standard normal inverse CDF; use an erfinv-based implementation or a precomputed table. Substituting energy distance or Cramer-von Mises for the Wasserstein term is a drop-in change.

## 17. Practical Recommendations

### 17.1 Choosing a variant

| Use case | Recommendation | Rationale |
|---|---|---|
| Unlabelled image pretraining | C-JEPA, or LeJEPA if minimising tuning | Best reported image numbers; LeJEPA has one hyperparameter |
| Video understanding | V-JEPA 2 | Strongest temporal reasoning, pretrained checkpoints available |
| Robotics and planning | V-JEPA 2-AC | Zero-shot goal-conditioned control, no reward engineering |
| Efficient vision-language perception | VL-JEPA | Fewer trainable params, selective decoding avoids needless generation |
| Audio representation learning | A-JEPA | Handles the time-frequency axis asymmetry |
| Improving an LLM's latent semantics | LLM-JEPA | No inference-time cost, requires paired views |
| Teaching, ablations, first implementation | I-JEPA | Simplest, best documented, public code |
| Long-horizon hierarchical planning | H-JEPA | Research direction, not a shipped model |

### 17.2 Implementation checklist

```
[ ] Encoder
    [ ] ViT trunk sized to available compute (B / L / H / g)
    [ ] Pre-norm blocks
    [ ] RoPE for images, 3D-RoPE for video
    [ ] Encoder processes ONLY visible tokens

[ ] Predictor
    [ ] Width 0.3-0.5x the encoder width
    [ ] 6-12 layers, fewer than the encoder
    [ ] Learnable mask token
    [ ] Position (and action, if applicable) conditioning present

[ ] Masking
    [ ] 4-8 target blocks
    [ ] 75-90% effective masking
    [ ] Context excludes the union of ALL target patches
    [ ] Video: identical spatial footprint across every frame
    [ ] Audio: blocks elongated in time

[ ] Collapse prevention
    [ ] Target encoder initialised as an exact copy of the context encoder
    [ ] Stop-gradient on the target branch
    [ ] EMA applied after the optimizer step, tau ramping 0.996 -> ~1.0
    [ ] Optional: VICReg (C-JEPA) or SIGReg (LeJEPA)

[ ] Training
    [ ] AdamW, weight decay 0.05, betas (0.9, 0.95)
    [ ] Cosine LR with long warmup
    [ ] Mixed precision, bf16 preferred over fp16 for EMA stability
    [ ] Gradient clipping

[ ] Monitoring
    [ ] Embedding singular value spectrum / effective rank
    [ ] Per-dimension standard deviation
    [ ] Periodic linear probe on a held-out labelled subset
    [ ] Loss trajectory shape, not just its value
```

### 17.3 Common pitfalls

| Pitfall | Symptom | Fix |
|---|---|---|
| Representation collapse | Loss near zero, features nearly constant | Check EMA ordering and decay; add VICReg or SIGReg |
| Dimensional collapse | Loss fine, probe plateaus, rank spectrum drops off a cliff | Add variance and covariance terms; raise batch size |
| Predictor too powerful | Low training loss, poor transfer | Reduce predictor width and depth |
| Masking ratio too low | Task is easy, features are weak | Raise to 75-90% |
| Per-frame masks in video | Loss falls fast, no motion understanding | Enforce a shared spatial footprint across frames |
| Missing position conditioning | Predictor cannot disambiguate targets; outputs converge | Add learnable position embeddings or RoPE to the predictor |
| EMA decay too low | Unstable training, oscillating loss | Start at 0.996 and ramp toward 1.0 |
| Target leakage into context | Suspiciously fast convergence | Assert that context and target index sets are disjoint |
| Small effective batch with VICReg or SIGReg | Regularizer is noisy or ineffective | Increase batch, or accumulate statistics across devices |
| fp16 with EMA | Teacher weights drift or stagnate | Use bf16, or keep the EMA copy in fp32 |

### 17.4 Future directions

1. **Hierarchical JEPA (H-JEPA):** learned multi-scale abstractions for long-horizon planning, rather than hand-specified levels.
2. **Multimodal JEPA:** one architecture over vision, language, audio, and actions in a shared latent space.
3. **Efficient JEPA:** linear or sparse attention to extend context to long videos and high resolution.
4. **Online and continual JEPA:** streaming updates without catastrophic forgetting; the EMA teacher is a natural anchor.
5. **Sparse and MoE JEPA:** conditional computation for scaling encoder capacity without proportional FLOPs.
6. **Theory of anti-collapse:** LeJEPA's provable guarantee suggests the heuristic stack (EMA, stop-grad, bottleneck) can be replaced wholesale by distributional constraints.

Additional caveats worth carrying forward:

- **Dates and identifiers.** Publication dates and arXiv identifiers for the more recent entries (V-JEPA 2, VL-JEPA, LeJEPA, LLM-JEPA) came from the source documents and were not independently verified here. Confirm against arXiv before citing.
- **Benchmark comparability.** Linear probe versus attentive probe versus full fine-tuning are different protocols. Compute figures likewise depend on hardware generation, resolution, and epoch budget.
- **C-JEPA's ranking claim.** "Best on images" is time-stamped and volatile in this field.
- **Code listings are reference implementations,** not the official repositories. They show structure and the critical invariants (stop-gradient, EMA ordering, mask disjointness) and omit distributed training, checkpointing, and throughput optimizations.
- **Mixed Keras and NumPy and TensorFlow.** The blueprints use `keras.ops` for portability but the trainer example uses `tf.GradientTape`; adapt to your backend.
