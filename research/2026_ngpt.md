# nGPT: Normalized Transformer with Representation Learning on the Hypersphere

Nov 4, 2026 · @Nikolas Markou

## Overview

nGPT constrains every vector in a Transformer (embeddings, weight-matrix rows, hidden states) to the unit hypersphere and turns each residual update into a learned interpolation step on that sphere; on OpenWebText it reaches GPT's validation loss in 4x to 20x fewer tokens, with the gain growing with context length.

**Paper.** Ilya Loshchilov, Cheng-Ping Hsieh, Simeng Sun, Boris Ginsburg (NVIDIA). *nGPT: Normalized Transformer with Representation Learning on the Hypersphere*. [arXiv:2410.01131](https://arxiv.org/abs/2410.01131) (v1 1 Oct 2024, v2 23 Apr 2025). Published at ICLR 2025 ([proceedings](https://proceedings.iclr.cc/paper_files/paper/2025/hash/b7c12689a89e98a61bcaa65285a41b7c-Abstract-Conference.html)). License CC BY 4.0. Reference code (nanoGPT re-implementation): [github.com/NVIDIA/ngpt](https://github.com/NVIDIA/ngpt). This brief follows v2.

**Core idea in four steps**

1. Normalize every embedding vector and every row of every weight matrix (along the embedding dimension) to unit norm after each optimizer step. Every matrix-vector product becomes a set of cosine similarities in [-1, 1].
2. Keep the hidden state h on the unit sphere. Each attention or MLP block proposes a normalized target point; h moves part of the way toward it and is renormalized.
3. The step size per dimension is a learned vector, the eigen learning rates alpha_A and alpha_M. The network itself behaves like a multi-step variable-metric optimizer on the sphere, two steps per layer.
4. Learnable scaling factors (s_qk, s_u, s_v, s_z) restore the magnitude information that normalization removes, where nonlinearities and softmax need it.

**Headline results**

| Result | Value |
| --- | --- |
| Speedup to equal validation loss, 1k / 4k / 8k context | about 4x / 10x / 20x fewer tokens (0.5B and 1B models) |
| 1B, 4k context example | nGPT at 20k iterations matches GPT at 200k (about 400B tokens) |
| Downstream tasks | Same acceleration pattern as validation loss |
| Wall-clock cost per step | 80% higher at 4k, 60% higher at 8k (unfused normalization code) |
| Removed from training | All LayerNorm/RMSNorm layers, weight decay, learning-rate warmup |
| Conditioning | Much lower condition numbers in embeddings and attention matrices than GPT |
| Length extrapolation | Stable PG19 perplexity beyond training length without RoPE changes |

## Background concepts

nGPT combines four older ideas: normalization layers, weight-norm control, hyperspherical representations, and the view of a Transformer as an optimizer running inside its forward pass.

**The baseline (pre-norm) Transformer block.** For a hidden state h in R^d_model, each of L layers applies:

```latex
h \leftarrow h + \mathrm{ATTN}(\mathrm{RMSNorm}(h)), \qquad h \leftarrow h + \mathrm{MLP}(\mathrm{RMSNorm}(h))
```

RMSNorm rescales h to norm sqrt(d_model), then multiplies each dimension by a learnable gain (initialized to 1). Because block outputs are added to h, the norm of h drifts across layers, so a final RMSNorm is applied before the output head. Weight matrices are unconstrained; their norms are managed indirectly with weight decay.

**Unit hypersphere.** The set of vectors with L2 norm 1. For unit vectors a and b, the dot product a·b equals cos(theta), the cosine of the angle between them. Norm(x) = x / ||x|| projects any non-zero vector onto the sphere, with no learnable gain (unlike RMSNorm or LayerNorm).

**Why hyperspheres.** Prior work links spherical representations to more stable training and better-separated embeddings: contrastive learning (alignment and uniformity, Wang and Isola, 2020), face verification (NormFace), spherical VAEs, hyperspherical prototype networks, and the normalized training dynamics of EDM2 diffusion models (Karras et al., 2024).

**SLERP and LERP.** Spherical linear interpolation moves along the geodesic (shortest arc) between two points on the sphere:

```latex
\mathrm{SLERP}(a, b; \alpha) = \frac{\sin((1-\alpha)\theta)}{\sin\theta}\,a + \frac{\sin(\alpha\theta)}{\sin\theta}\,b, \qquad \theta = \arccos(a \cdot b)
```

Linear interpolation, LERP(a, b; alpha) = (1 - alpha) a + alpha b, cuts through the sphere's interior; renormalizing the result approximates SLERP. alpha = 0 returns a, alpha = 1 returns b.

**Variable-metric (quasi-Newton) updates.** A gradient step x ← x - alpha g can be generalized to x ← x - alpha B g, where B approximates the inverse Hessian. If B is diagonal and non-negative, alpha B collapses to a vector of per-coordinate step sizes.

**Riemannian optimization and retraction.** Optimizing on a curved manifold such as the sphere means stepping in the tangent space, then mapping back onto the manifold. That mapping is a retraction; for the sphere, simple renormalization is one.

**Transformers as meta-optimizers.** Von Oswald et al. (2023) and Dai et al. (2022) argue that in-context learning resembles implicit gradient descent inside the forward pass. nGPT makes this literal: each block proposes a direction and h takes a learned step toward it.

**Adam's effective learning rate.** Adam's update is roughly lr × m / sqrt(v), with m / sqrt(v) usually near ±1. So each parameter moves by about lr per step regardless of its scale. A parameter of size 0.01 doubles in about 10 steps at lr 0.001; one of size 1.0 needs about 1000. nGPT uses this to set separate effective learning rates for its scaling parameters (see Mechanism).

**SwiGLU.** The gated MLP activation SwiGLU(u, v) = u · SiLU(v), with SiLU(x) = x · sigmoid(x). SiLU behaves like ReLU for large |x| and like x/2 for x near 0; its minimum is about -0.278 at x ≈ -1.278.

## Architecture: GPT versus nGPT

nGPT replaces every normalization layer with unit-norm constraints on weights and states, and replaces the residual sum with a normalized interpolation; every other component (RoPE, SwiGLU, causal attention) is kept.

**Side-by-side (paper's Table 1)**

| Step | GPT (baseline) | nGPT |
| --- | --- | --- |
| Attention output | h_A ← ATTN(RMSNorm(h)) | h_A ← Norm(ATTN(h)) |
| Attention update | h ← h + h_A | h ← Norm(h + alpha_A (h_A - h)) |
| MLP output | h_M ← MLP(RMSNorm(h)) | h_M ← Norm(MLP(h)) |
| MLP update | h ← h + h_M | h ← Norm(h + alpha_M (h_M - h)) |
| After last layer | h ← RMSNorm(h) | Nothing (h already unit norm) |
| Weights | Unconstrained | Every matrix and embedding normalized along the embedding dimension after each optimizer step |

### Token embeddings and logits

- Input and output embedding matrices E_input, E_output (V × d_model) are both row-normalized after every step, so token similarity is a true cosine similarity rather than one distorted by embedding norms.
- Logits z = E_output h are therefore bounded in [-1, 1], which would cap softmax confidence. A learnable per-token scale s_z in R^V fixes this (following Hoffer et al., 2018):

```latex
z \leftarrow z \odot s_z
```

### Self-attention block

- W_q, W_k, W_v and W_o are normalized along the embedding dimension, so each projection is a set of cosine similarities between h and stored unit vectors.
- After projection and RoPE, q and k can still have varying norms (RoPE distorts them further). nGPT renormalizes them per head and applies one shared learnable scale vector s_qk in R^d_k per head:

```latex
q \leftarrow \mathrm{Norm}(q)\, s_{qk}, \qquad k \leftarrow \mathrm{Norm}(k)\, s_{qk}
```

- One vector suffices for both, since the scales multiply elementwise inside the q·k product.
- Softmax scaling changes from 1/sqrt(d_k) to sqrt(d_k). Reason: the dot product of two random unit vectors in d_k dimensions has variance 1/d_k, so multiplying by sqrt(d_k) restores unit variance. Using a scale of 1 instead is equivalent to initializing s_qk at d_k^(1/4).

### MLP block

- W_u and W_v (the two input projections) are normalized, so u and v are cosine similarities with stored vectors. Learnable scales s_u, s_v in R^d_MLP restore magnitude:

```latex
u \leftarrow u \odot s_u, \qquad \nu \leftarrow \nu \odot s_\nu \sqrt{d_{\text{model}}}
```

- The extra sqrt(d_model) on v matters: random cosines in d_model dimensions have expected magnitude about 0.80 / sqrt(d_model), tiny inputs on which SiLU is nearly linear (≈ x/2). Rescaling restores unit variance so SiLU acts as a real nonlinearity (App. A.1).
- The MLP output is invariant to scaling u by a constant, so s_u mainly redistributes magnitude across units.
- The output projection W_oMLP is also normalized, and the block output is normalized: h_M = Norm(MLP(h)).

### Matrices normalized after each step

E_input, E_output, W_q, W_k, W_v, W_o, W_u, W_v and W_oMLP, each along its embedding dimension.

## Mechanism: the network as an optimizer on the sphere

Each token's hidden state starts at its input embedding on the sphere and is moved, two steps per layer, toward a point that predicts the next token's output embedding; the attention and MLP blocks supply the directions and the eigen learning rates supply the step sizes.

### From interpolation to a gradient step

Start from LERP and rewrite it as an update, with a = h (current state) and b = the block's suggestion:

```latex
a \leftarrow a + \alpha(b - a)
```

Define the "gradient" g = a - b. Generalizing the scalar step to a variable-metric matrix B gives a ← a - alpha B g. With B diagonal and non-negative, alpha B becomes a vector. The resulting block updates:

```latex
h \leftarrow \mathrm{Norm}\big(h + \alpha_A \odot (h_A - h)\big), \qquad h \leftarrow \mathrm{Norm}\big(h + \alpha_M \odot (h_M - h)\big)
```

with h_A = Norm(ATTN(h)), h_M = Norm(MLP(h)) and alpha_A, alpha_M in R^d_model, non-negative. The final Norm is the retraction back onto the sphere.

**Eigen learning rates.** The authors name alpha_A and alpha_M "eigen" learning rates (German eigen, "own"): the network's own internal step sizes, i.e. the diagonal of a learned variable-metric matrix. They are directly interpretable: alpha_A,i = 0.2 means h_i ← 0.8 h_i + 0.2 h_A,i, so 20% of dimension i comes from the attention block.

### Why this is not ReZero or NormFormer (App. A.2)

| Method | Update | Key difference from nGPT |
| --- | --- | --- |
| ReZero (Bachlechner et al., 2020) | h ← h + alpha h_T, one scalar per layer, initialized at 0 | Scales the block output's value, not the direction to it. alpha can be absorbed into the output matrix, so it does not measure the block's contribution. h's norm is unconstrained |
| NormFormer (Shleifer et al., 2021) | Extra LayerNorms inside blocks and a scaled residual | Does not normalize parameters or keep h on the sphere; h's growing norm still affects how block outputs combine |
| nGPT | h ← Norm(h + alpha_T (Norm(h_T) - h)) | Invariant to rescaling the output projection, so alpha_T truly measures the block's contribution; h stays on the sphere |

**Sign of alpha.** The paper constrains alpha ≥ 0 for interpretability (alpha ← |alpha| in the forward pass). Unconstrained alpha gives the same results, because Adam can flip the sign of the matching row of the output projection instead. Negative entries would correspond to exploiting negative curvature, as some Riemannian methods do.

### The full Riemannian version (App. A.4)

Treating h - h_A as a Euclidean gradient, its projection onto the sphere's tangent space is:

```latex
g_{\text{proj}} = h\,(h^{\top} h_A) - h_A
```

This ranges from h - h_A (when h and h_A are aligned) to -h_A (when orthogonal). The corresponding update is h ← Norm(h - B_A (h (h^T h_A) - h_A)), and likewise for the MLP. The authors found the h^T h_A factor had negligible effect, so all experiments use the simpler LERP-style update.

### Controlling how fast each scale parameter learns

Adam moves every parameter by roughly the learning rate per step, regardless of its size (see Background). To give each trainable scale vector s_a its own effective learning rate without a separate optimizer group, nGPT stores it at a reference scale and rescales in the forward pass:

- Two constants per vector: s_a,init (the value used in the forward pass at initialization) and s_a,scale (the value actually stored).
- The parameter is initialized to s_a,scale; the forward pass uses s_a × (s_a,init / s_a,scale).
- A smaller s_a,scale makes the stored number smaller, so the same Adam step is a larger relative change: a higher effective learning rate. s_a,scale = 1/sqrt(d_model) matches the effective rate of the normalized weight entries.

**Parameter settings used (Sec. 2.6)**

| Parameter | Role | s_init | s_scale |
| --- | --- | --- | --- |
| alpha_A, alpha_M | Eigen learning rates (attention, MLP) | 0.05 (order 1/n_layers) | 1/sqrt(d_model) |
| s_qk | Query/key scale per head | 1 | 1/sqrt(d_model) |
| s_u, s_v | MLP intermediate scales | 1 | 1 |
| s_z | Per-token logit scale | 1 | 1/sqrt(d_model) |

## Training recipe and setup

Converting GPT to nGPT takes seven changes; the only hyperparameter tuned for either model is the initial learning rate.

**The seven-step conversion (Sec. 2.6)**

1. Remove all normalization layers (RMSNorm, LayerNorm).
2. After each training step (optionally also in the forward pass), normalize E_input, E_output, W_q, W_k, W_v, W_o, W_u, W_v and W_oMLP along their embedding dimension.
3. Replace the residual sums with the normalized interpolation updates, using alpha_A and alpha_M with init 0.05 and scale 1/sqrt(d_model).
4. Change the attention softmax scale from 1/sqrt(d_k) to sqrt(d_k); normalize and rescale q and k with s_qk (init 1, scale 1/sqrt(d_model)). The q/k normalization is optional.
5. Rescale the MLP intermediate states with s_u and s_v (init 1, scale 1).
6. Rescale logits with s_z (init 1, scale 1/sqrt(d_model)).
7. Remove weight decay and learning-rate warmup.

**Implementation pitfall flagged by the authors.** Normalize the parameter tensors the optimizer actually updates, not just the model's instantiated copies. Missing this is a common bug.

**Shared setup (App. A.6)**

- Data: OpenWebText (Gokaslan and Cohen, 2019), an open approximation of GPT-2's training set. The authors acknowledge it is not the highest-quality corpus but favor comparability.
- Tokenizer: LLaMA-2, 32k vocabulary.
- Hardware: 64 A100 GPUs (8 nodes × 8). Global batch size 512 sequences.
- Precision: matrix parameters stored in bfloat16.
- Initialization: GPT matrices from N(0, 0.02); nGPT from N(0, 1/sqrt(d_model)), largely irrelevant since they are normalized immediately. Output matrices scaled down by sqrt(2 × n_layers) (GPT-2 practice). RoPE base 10,000.
- Framework: an internal Megatron-LM-based library. The public nanoGPT re-implementation only qualitatively reproduces the results and is not meant for production.

**Learning-rate tuning (App. A.7).** Optimal initial learning rates for GPT and nGPT were similar at equal validation loss; longer runs preferred lower rates. One instability: the 1B nGPT at 8k context became sensitive to learning rate. Raising the alpha_A, alpha_M scale constant from 1/sqrt(d_model) to 0.1 slowed their effective learning rate about 3x and restored smooth behavior. (The appendix text calls this the init value; the 3x arithmetic matches the scale constant.)

## Experiments and results

At matched token budgets nGPT reaches GPT's loss and downstream accuracy with 4x (1k context), 10x (4k) and 20x (8k) fewer tokens, at both 0.5B and 1B parameters; the per-step cost is higher, so the wall-clock gain is smaller than the token gain.

**Acceleration by context length (Fig. 1, 2)**

| Context length | Token speedup (0.5B and 1B) | Step-time overhead of nGPT |
| --- | --- | --- |
| 1k | about 4x | not reported |
| 4k | about 10x | about +80% |
| 8k | about 20x | about +60% |

Rough wall-clock implication (our arithmetic, not a paper claim): 10x fewer steps at 1.8x the step time is about 5.6x less time at 4k; 20x at 1.6x is about 12.5x at 8k. The authors expect the overhead to shrink with fused kernels and larger models, since the number of layers, and so of normalizations, grows only modestly with parameter count.

**Concrete example (Fig. 1).** 1B models, 4k context: nGPT reaches at 20k iterations the validation loss GPT reaches at 200k iterations (about 400B tokens).

**Downstream tasks (Fig. 3, 8, 9).** Accuracy on a set of standard downstream tasks and their average shows the same acceleration as validation loss, at 1k, 4k and 8k context. The longest nGPT runs show some saturation, which the authors attribute to approaching the capacity of models this size.

**Few-shot translation (Fig. 10).** WMT14 French-to-English with five example pairs, scored by BLEU, following the GPT-2 evaluation protocol.

**Length extrapolation (App. A.8, Fig. 14).** On PG19, evaluated from 1k to 32k tokens:

- GPT's perplexity rises sharply beyond its training length.
- nGPT stays in a stable perplexity range at extrapolated lengths, with no RoPE modification.
- Removing q/k normalization noticeably worsens extrapolation, even though in-distribution loss and accuracy are unchanged. q/k normalization re-bounds q·k after RoPE.
- nGPT without q/k normalization still extrapolates much better than GPT. The authors partly attribute this to GPT's near low-rank attention matrices; Kobayashi et al. (2024) showed weight decay induces low-rank attention, and nGPT uses none.

## Analysis of the trained networks

nGPT's embeddings and attention matrices are far better conditioned than GPT's, and its learned step sizes show each block moving the hidden state only 20% to 37% of the way toward its suggestion.

### Embeddings (Fig. 4, models trained 100k iterations)

- **Norms.** nGPT embeddings have unit norm by construction; GPT's vary widely, forming a hyper-ellipsoid rather than a sphere.
- **Conditioning.** Eigenvalues of the embedding covariance, divided by their median, show a higher condition number for GPT's input embeddings, especially at 1B. Ill-conditioning can cause numerical problems in computations involving these embeddings.
- **Clustering.** Pairwise dot products in nGPT are not near 0, as uniform spread over the sphere would give. Embeddings cluster, plausibly reflecting structure in language. GPT's dot products run higher, consistent with its ellipsoidal shape.

### Attention and MLP matrices (Fig. 5, 11, 12, 13)

- GPT's attention matrices have much higher median condition numbers than nGPT's across layers (24 layers at 0.5B, 36 at 1B).
- Singular-value plots for layers 3 and 4 suggest GPT's attention matrices degenerate toward low rank, possibly limiting capacity.
- Renormalizing GPT's matrices after training lowers their condition numbers but not to nGPT's level, pointing to genuine rank deficiency rather than a norm artifact.

### Learned step sizes and scales (Fig. 6, 15)

| Quantity | 0.5B (24 layers) | 1B (36 layers) | Reading |
| --- | --- | --- | --- |
| Mean alpha_A | 0.25 | 0.20 | Attention moves h about 20% to 25% toward h_A |
| Mean alpha_M | 0.37 | 0.32 | MLP steps are larger, perhaps because MLPs hold more parameters and predict better |

- Deeper models take smaller steps per block, as expected with more layers sharing the work.
- Longer context and more training tokens shift alpha distributions upward: h needs more transformation for larger inputs. Learning rate barely affects them.
- s_u, s_v and s_qk are fairly stable across layers. s_v can be read as how nonlinear SiLU is: large values make it ReLU-like, values near 0 make it nearly linear.
- s_qk is stable under all conditions, suggesting a fixed value (like the classic softmax scale) could suffice. It has high density near zero, which the authors read as attention sparsity.
- s_u and s_v shift lower with longer context, and higher with larger models or more tokens; they flatten at larger learning rates.
- s_z is mainly characterized by its mean, which sets the softmax temperature. It rises with context length, model size and training tokens: the model learns sharper (lower-temperature) output distributions.
- Overall, the scale factors appear to compensate for the magnitude information that normalization strips out.

## Limitations, reproductions and open questions

Independent work reproduces nGPT's faster convergence but at smaller factors (a community reproduction measures about 1.5x to 4x rather than 4x to 20x), and points to the paper's multi-epoch training on a small dataset and its BF16-stored baseline weights as likely reasons.

**Limitations visible in the paper**

- **Small dataset, many epochs.** OpenWebText has roughly 9B tokens; runs of up to about 400B tokens repeat it dozens of times. Speedups measured under heavy data repetition may not hold in single-epoch training on large corpora.
- **Scale.** Largest model is 1B parameters. The authors list larger models, real-world datasets and more tasks as future work.
- **Wall-clock cost.** Steps are 60% to 80% slower in the authors' unfused implementation, shrinking the real-time gain.
- **Baseline choices.** GPT uses BF16-stored matrix parameters, weight decay 0.1 and no q/k normalization; each choice affects how strong the baseline is.
- **Saturation.** The longest nGPT runs plateau, which the authors attribute to model capacity.
- **Tuning sensitivity.** The 1B, 8k-context model needed a change to the eigen learning rates' effective step size to train smoothly.
- **Mechanism evidence is correlational.** Better conditioning and the optimizer interpretation are consistent with the speedup but not shown to cause it.

Attributes the gap to the GPT baseline improving when its parameters are stored in FP32, while nGPT's results match the paper |

The second reproduction supports a reading where part of nGPT's advantage is robustness to low-precision weight storage, which hurts the unnormalized baseline more.

**Open questions**

- Does the speedup persist at multi-billion-parameter scale and in single-epoch training on high-quality data?
- How much of the gain remains against a modern, strong baseline (FP32 master weights, q/k normalization, tuned weight decay)?
- Can fused kernels remove the step-time overhead?
- How does nGPT interact with mixture-of-experts, encoder-decoder and hybrid state-space architectures (the authors call these extensions straightforward)?
- Can the spherical structure support new optimizers or analysis tools, which the authors frame as the larger opportunity?

## Related work and expanded references

nGPT's lineage runs through weight normalization and norm control, hyperspherical representation learning, q/k normalization, and Transformers-as-optimizers; the authors say it was designed from first principles, starting from Loshchilov's earlier work on weight-norm control.

**How nGPT came about (App. A.3).** Loshchilov (2023) replaced weight decay with explicit, scheduled control of parameter norms in AdamW, which sped up training. Attention matrices stayed ill-conditioned even when whole matrices were normalized, but normalizing individual vectors inside them helped. Combined with the observation that LayerNorm/RMSNorm (with equal gains) already project h onto a sphere, this led to making every vector spherical, with SLERP as the natural way to combine states and scale factors to relax the constraints.

## Glossary

| Term | Meaning |
| --- | --- |
| alpha_A, alpha_M | Eigen learning rates: per-dimension step sizes for the attention and MLP updates |
| Condition number | Ratio of largest to smallest singular value (or eigenvalue); high values mean ill-conditioned, near low-rank matrices |
| d_k | Per-head query/key dimension, d_model / n_heads |
| Eigen learning rate | A learned, per-dimension step size inside the network, read as the diagonal of a variable-metric matrix |
| Geodesic | Shortest path between two points on a curved surface; a great-circle arc on a sphere |
| h_A, h_M | Normalized outputs of the attention and MLP blocks: the points the hidden state moves toward |
| LERP | Linear interpolation (1 - alpha) a + alpha b; renormalized, it approximates SLERP |
| Norm(x) | x / ‖x‖, projection onto the unit sphere with no learnable gain |
| q/k normalization | Normalizing query and key vectors per head before the dot product |
| Retraction | Mapping a point back onto a manifold after a step; here, renormalization |
| ReZero | Residual connection gated by a zero-initialized learnable scalar |
| s_a,init / s_a,scale | Forward-pass value at initialization / stored value of a scale parameter; their ratio sets its effective learning rate under Adam |
| s_qk | Learnable per-head scale on normalized queries and keys |
| s_u, s_v | Learnable scales on the MLP's gate and value branches |
| s_z | Learnable per-token logit scale; its mean sets the softmax temperature |
| SLERP | Spherical linear interpolation along the geodesic |
| SwiGLU, SiLU | Gated MLP activation u · SiLU(v); SiLU(x) = x · sigmoid(x) |
| Unit hypersphere | All vectors of L2 norm 1; dot products between them are cosines in [-1, 1] |
| Variable-metric method | Optimizer that rescales the gradient by a learned matrix (quasi-Newton when it approximates the inverse Hessian) |
