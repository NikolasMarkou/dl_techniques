## 1. What MoGe is (verified)

Single-image **metric** geometry in one forward pass: a dense point map, a depth map, a
validity mask, (V2/V3) a normal map, a per-image metric scale, and — in `infer()` only —
recovered camera intrinsics/FOV.

Coordinate convention (`README.md`, and `v2.infer` docstring): OpenCV camera space,
**x right, y down, z forward**. Intrinsics are **normalized** (principal point at
`(0.5, 0.5)`), and the focal is expressed **relative to half the image diagonal** — a
different parameterisation from this repo's pixel-space intrinsics (§10).

### 1.1 The inference contract

```
infer(image (B,3,H,W) float [0,1],
      num_tokens: int | None = None,
      resolution_level: int = 9,        # 0..9 → num_tokens interpolated over num_tokens_range
      force_projection: bool = True,    # recompute points from depth + intrinsics
      apply_mask: bool = True,          # invalid pixels → +inf
      fov_x: float | Tensor | None = None,
      refine_steps: int = 3,            # V3 only
      return_per_step: bool = False,    # V3 only
      use_fp16: bool = ...)
  -> {points (B,H,W,3), depth (B,H,W), intrinsics (B,3,3), mask (B,H,W) bool,
      normal (B,H,W,3)?, points_per_step/depth_per_step/intrinsics_per_step?}
```

`forward()` is the training-path signature: `forward(image, num_tokens)` for V1/V2,
`forward(image, num_tokens, refine_steps, refiner_detach_backbone, return_per_step)` for V3.
Both accept only **image and token count** — see §3.2.

### 1.2 Versions

| Ver | Encoder | Neck / heads | Outputs | Params |
|---|---|---|---|---|
| **V1** | vendored DINOv2 (`modules/dinov2/`), `get_intermediate_layers(x, 4)` | `Head` (in `v1.py`): 1×1 `projects` summed → 3 × [`ConvTranspose2d(k=2,s=2)` + 3×3 conv] + `ResidualConvBlock`, UV concat at every stage, then 3×3 → 32ch → ReLU → 1×1 → `[3,1]` | affine-invariant points, mask logits | 314M (vitl) |
| **V2** | `DINOv2Encoder`: resize to `(token_rows*14, token_cols*14)`, ImageNet normalise, taps `[5,11,17,23]`, **1×1 `output_projections` summed** | `ConvStack` neck + `points_head` / `normal_head` / `mask_head` (each its own `ConvStack`) + `scale_head` MLP on the CLS token | metric points (`exp` remap), unit normals, sigmoid mask, `exp(metric_scale)` | 326M (vitl) / 331M (vitl-normal) |
| **V3** | same as V2 | + `Sparse3DUNet` refiner over `(x/z, y/z, logz)` voxels, `refiner_depth_resolution=256`, `refine_steps=3` | V2 outputs + per-step points/depth/intrinsics | 370M (vitl) / 1.25B (vitg) |

### 1.3 Machinery that must be ported or replaced

`_remap_points {linear, sinh, exp, sinh_exp}`; `normalized_view_plane_uv`;
`recover_focal_shift` (64×64 nearest downsample → `scipy.optimize.least_squares`);
`mask_aware_nearest_resize`; `intrinsics_from_focal_center`; `depth_map_to_point_map`
(both from `utils3d`); gradient-checkpointing / autocast wrappers; `from_pretrained`
(HF `model.pt` → `checkpoint['model_config']` + `checkpoint['model']`, `strict=False`
**with an explicit missing/unexpected-key warning**); `init_weights` from torch.hub
DINOv2; `onnx_compatible_mode`.

Losses (`moge/train/losses.py`) and the alignment core (`moge/utils/alignment.py`) are
§12 and §11 respectively. Data and eval (`train/dataloader.py`, `test/*`) are §14.

Three consequences that shape the implementation:

1. **`res_block_in_norm`/`res_block_hidden_norm` are `"none"` for the released V2/V3
   checkpoints** — every conv in the neck and heads is `Identity → act → conv`. GroupNorm
   is therefore required only for **V1** (`v1.ResidualConvBlock` defaults to
   `GroupNorm(1, C)` then `GroupNorm(C//32, hidden)`), but `ResidualConvBlock` must still
   support all four norm modes because the upstream ctor exposes them.
2. **Replicate padding is used everywhere** (`padding_mode='replicate'` on every 3×3), so it
   is required for all three versions.
3. **`encoder_channels: 1026` is the level-0 encoder feature *after* the UV concat**
   (`1024 + 2`). The refiner is conditioned on encoder features, not on points alone.

### 2.1 Variant table decision

Only the **vitl** configurations are published. The `vits`/`vitb` dimensions live solely
inside each `model.pt`'s `model_config`, which needs `torch` to unpickle and torch is not a
dependency of this repo. Per the v2 guide §5.6 ("no invented scales"), this plan ships
**four variants whose configs are citable**:

| Variant name | Class | Config source | Notes |
|---|---|---|---|
| `moge-vitl` | `MoGeV1` | `configs/train/v1.json` | affine-invariant, no normals, no metric scale |
| `moge-2-vitl` | `MoGeV2` | `configs/train/v2.json`, `normal_head` removed | derived-by-removal; see caveat |
| `moge-2-vitl-normal` | `MoGeV2` | `configs/train/v2.json` verbatim | the full training config |
| `moge-3-vitl` | `MoGeV3` | `configs/train/v3.json` | refiner included |

Caveat on the derived row: `moge-2-vitl` is the published training config with the
`normal_head` key deleted, because `v2.py`'s ctor takes `normal_head: Dict | None = None`
and `forward` guards it with `hasattr`. The training config contains every head, so which
key set the *released* `moge-2-vitl` checkpoint carries is not knowable from the repo —
record it as **derived**, and re-check it if anyone ever introspects the checkpoint.

The `moge-2-vitl` / `moge-2-vitl-normal` pair is not a duplicate: it is the only pair in
the table that exercises the optional-head path, which is what the anti-vacuity guard in
§9.2 needs.

* **Docstrings:** Sphinx/reST in `models/`, Google in `losses/`. A substantive module

| `models/vision/vit/model.py ViT` | `normalization_position='post'` default (DECISION D-047, deliberately not flipped); its `get_intermediate_layers` has the same last-`n` limit; no registers/LayerScale |
| `DPTDecoder` | §3.3 |
| `TransformerLayer` for DINOv2 blocks | Its pre-norm branch applies stochastic depth **before** layer scale (`transformer.py:998-1001`) where DINOv2 applies `LayerScale → DropPath`; two `StochasticDepth` instances instead of one. Multiplication commutes with a per-sample dropout mask in exact arithmetic, so it is not a numerical divergence — but it is a second block class in the tree for no benefit |
| `PixelShuffle` (`layers/pooling`) | It is a **token-sequence** layer: `(B, 1+H*W, C) → (B, 1+HW/s², C·s²)` with CLS handled separately, not the NHWC space-to-depth `Resampler('pixel_shuffle')` needs. `PixelUnshuffle2D` **is** the right NHWC downsample for `pixel_unshuffle`/`avg_pool`/`max_pool` modes |

## 6. The encoder problem, in full (D-1)

MoGe needs three things the in-tree DINOv2 cannot give:

1. **A per-call token grid.** `forward` computes
   `base_h = round(sqrt(num_tokens / aspect))`, `base_w = round(sqrt(num_tokens * aspect))`
   and resizes the image to `(base_h*14, base_w*14)`. During training the aspect ratio and
   area are randomised per sample (`area_range [250e3, 1e6]`, `aspect_ratio_range [0.5,2]`),
   so **the grid changes every step**. A Functional model with a construction-time
   `output_grid` cannot do this.
2. **Taps at arbitrary depths** — blocks `[5,11,17,23]` of 24, not the last four.
3. **ImageNet normalisation inside the encoder** — the reference does it in
   `DINOv2Encoder.forward`; this repo's `dino/` deliberately does none (no mean/std anywhere
   in `models/vision/dino/`).

### 6.1 The chosen shape: a new `DINOv2Backbone` in `models/vision/dino/`

`models/vision/dino/dinov2_backbone.py` — an **imperative** `keras.Model` (not Functional),
registered `@register_dl_technique("dl_techniques.models.dino.dinov2_backbone")`:

```
call(images, training=None) -> {"patch_tokens", "cls_token"}
  1. ImageNet standardise: (x - mean) / std, buffers (1,3,1,1), NOT learnable
  2. create_embedding_layer('patch_2d', patch_size=14, embed_dim=D,
                            kernel_initializer=TruncatedNormal(stddev=0.02))
  3. prepend cls token; splice `num_register_tokens` register tokens
  4. + dynamic positional embedding  ← the new part, see 6.2
  5. for block in self.transformer_blocks: x = block(x, training=training)
  6. x = create_normalization_layer('layer_norm')(x)          # the shared final norm
  7. return {"cls_token": x[:,0], "patch_tokens": x[:, 1+R:]}

tap(images, layer_indices, training=None) -> List[(B, N, D)]
  1..4 as above, then walk the block list, snapshotting x at each requested index
  5. apply the SAME final norm object to each snapshot (reference semantics:
     upstream DINOv2's `get_intermediate_layers` applies `self.norm` to every tap, so
     the norm weights are shared across taps — this repo's existing
     `get_intermediate_layers` already does the same at `dino_v2.py:1243-1244`)
  6. drop cls + registers
```

Because `DINOv2Block` is reused **verbatim**, the block stack, LayerScale behaviour,
stochastic-depth ramp, SwiGLU giant variant and `get_config` surface are the ones already
verified against official checkpoints and against `transformers` at 4 printed decimals
(`dino/README.md:89-93`). The new code is the stem and the tap walk.

### 6.2 The positional embedding, and why it is the risky bit

`DINOv2PositionEmbedding` (`dino_v2.py:212`) owns a `(1, 1+M², D)` table and resamples it
with **torch bicubic** at `scale_factor = (n + interpolate_offset)/M`
(`TORCH_BICUBIC_A = -0.75`, `dino_v2.py:106-109`) — and it takes `output_grid` as a
**construction-time** argument (`:252`). Official checkpoints ship the `M = 37` grid
(`official_weights.py:77`).

So `DINOv2Backbone` needs the same bicubic resample evaluated against the **runtime** grid.
Rules for that port:

* Reproduce `torch_bicubic_resize_matrix` exactly (`dino_v2.py:109`) as a pure helper, and
  test the runtime path against the **static** path at a matching grid — if they disagree,
  the static one is the oracle (it is what the official weights were verified against).
* Keep `interpolate_offset` (0.1) and `interpolate_antialias` (`True` only with
  `pos_embed_grid_size`) exactly as the existing layer parameterises them; do not introduce
  a second interpolation path.
* Guard the runtime shapes: `n` must equal `rows*cols` of the actual patch grid, and the
  helper must be used from `build`, `call` and `compute_output_shape` alike (v2 guide §3.4).
* **Mixed-precision arm**: the resample is an interpolation over a learned table; under
  `mixed_float16` the table is fp32 and the multiply must be cast, exactly like
  `LayerScale.call`'s mandatory cast (`layer_scale.py:203-205`).

### 6.3 Why not the alternatives

* **Make `DINOv2PositionEmbedding.output_grid` dynamic in place** — one fewer ViT in the
  tree, but it changes behaviour for DINOv2-2D×2.5, DINOv3 and Depth-Anything and puts
  dynamic shapes under mixed precision in shared code. Rejected as blast radius.
* **Fix the token grid at build time** (construct per-resolution Functional backbones) —
  loses `resolution_level`/`num_tokens` entirely, changes the inference contract, and
  cannot train, because the grid varies per sample. Rejected on fidelity.

### 6.4 What to check it against

* A NumPy reference of the stem + a single block, as
  `tests/test_models/test_dino/dinov2_numpy_reference.py` already does for DINOv2 — a
  shared instrument with **no `test_` prefix**, consumed by a mirrored `test_*.py` that
  carries its own RED proof (v2 guide §13.4.3: never hand-transcribe the oracle).
* `tests/test_models/test_dino/test_the_dinov2_backbone_is_the_references.py` is the
  naming precedent for the "the backbone is the reference's" claim.
* A **liveness** arm: a wrong tap index must change the tap *values* (§13.4.5 — "the
  component responded" is not "the component is right"), and a positive liveness arm must
  go through the same detector as the absence assertion (§13.4.6).

## 7. ConvStack, ResidualConvBlock and the two init quirks

### 7.1 `ConvStack` semantics (from `conv_stack.py`)

For `len(dim_res_blocks) == 5` the released config, `forward` is:

```
x = None
for i in range(5):
    feature = input_blocks[i](in_features[i])        # 1x1 conv, or Identity when dim_in is None
    x = feature if i == 0 else x + feature           # ← NOTE: Identity returns in_features[i],
                                                       #   so "None" means "add the raw input map"
    x = res_blocks[i](x)                             # 0 blocks at levels 0 and 4
    out_features.append(output_blocks[i](x))         # 1x1 conv, or Identity when dim_out is None
    if i < 4: x = resamplers[i](x)
return out_features                                  # the model consumes only the LAST element
```

Three things a naive Keras transcription gets wrong:

* `Identity` is **not** "no skip" — it is "add the unprojected input", which is how DPT-style
  skip fusion works. With `dim_in` non-`None` it is a 1×1 conv instead. The released neck has
  `dim_in=[1026,2,2,2,2]` (projected) and the released heads have `dim_in=<every level>`
  (projected), so the Identity path is exercised only by non-shipped configs — implement it
  anyway, and pin both branches.
* The 5 input feature maps are `[encoder⊕uv, uv, uv, uv, uv]` at 1×/2×/4×/8×/16× the token
  grid. The model **constructs** the UV-only maps for levels with no encoder feature; it
  does not skip them.
* Only the last `output_blocks` entry is consumed (`features[-1]`), the others being dead
  compute that still carries weights (`dim_out=[null,null,null,null,3]`).

### 7.2 `ResidualConvBlock`

```
GroupNorm(in_channels//32 or 1 or instance) → act → Conv3x3(replicate) →
GroupNorm(hidden//32 or 1 or instance)      → act → Conv3x3(replicate)   ;  + skip
skip = Conv1x1 if in != out else Identity
```

* Norm modes `'group_norm' | 'layer_norm' | 'instance_norm' | 'none'`; note the *encoding*:
  `'layer_norm'` here means **`GroupNorm(1, C)`** (one group per sample), **not** a
  LayerNorm. `GroupNorm(C//32, C)` requires `C >= 32` — a `ValueError`, not a silent floor.
* **One shared class covers both V1 and V2/V3.** V1's in-file `ResidualConvBlock` is
  `GroupNorm(1, C)` → act → conv3 → `GroupNorm(hidden//32 or 1, hidden)` → act → conv3, which
  is exactly V2's class instantiated with `in_norm='layer_norm'`,
  `hidden_norm='group_norm'` — V2's own defaults. So a single
  `layers/conv_blocks/residual_conv_block.py` serves all three versions; **V1 gets no second
  copy** (a duplicate class of the same name is exactly the §9.7 trap).
* **V1 is the only shipped version that instantiates the norms at all** — V2/V3 configs pass
  `"none"`, so every conv in the shipped V2/V3 neck and heads is `Identity → act → conv`.
* Epsilon: `keras.layers.GroupNormalization` defaults to **1e-3** against torch's **1e-5**.
  Construct directly with an explicit `epsilon=1e-5` and cite it, copying the documented
  trap at `doc_scanner/components.py:329-349`. Do **not** route it through
  `create_normalization_layer` — there is no `group_norm` key, and adding one would attach
  the factory's 1e-6 to a norm whose reference is 1e-5.
* **Replicate padding must be written.** `keras.ops.pad` has no EDGE mode on TF, so
  `ReplicatePad2D(padding=1)` composes four edge slices (or a slice-concat per axis).
  Register it in `layers/conv_blocks/` alongside its own registration string — per
  `layers/AGENTS.md`, a general layer goes in its domain package, not inside a model
  directory (§9.1 step 3).
* Activations: `relu` / `leaky_relu(0.2)` / `silu` / `elu` — `resolve_activation_layer`
  covers all four; match the file's argument name.

### 7.3 `Resampler` — the two load-bearing init quirks

1. **`conv_transpose`** (3 of the 4 shipped resamplers): `ConvTranspose2d(k=f, s=f)` followed
   by a 3×3 conv, with `self[0].weight.data[:] = self[0].weight.data[:, :, :1, :1]` — i.e.
   **the transposed kernel is zeroed outside its top-left 1×1**, which makes it exact ×2
   nearest-neighbour upsampling rather than a learned upsample. Left at a default
   initialiser this is a *different function* with no shape symptom. Needs an explicit
   initialiser (or a post-build `kernel.assign`) plus a weight-value test.
2. **`pixel_shuffle`**: `w[i::s²] = w[0::s²]` and the same for the bias — the `s²` sub-pixel
   filters are **tied** at init. Same treatment. (Not used by any shipped variant; implement
   and pin it anyway because the registry advertises it.)
3. `nearest`/`bilinear` = `Upsample(scale_factor, align_corners=False)` + 3×3 conv;
   `pixel_unshuffle`/`avg_pool`/`max_pool` = the op + 3×3 conv, **conv first** for the pool
   modes.

## 8. Where the variants diverge from each other

Not cosmetic differences — three separate contracts:

| | V1 | V2 | V3 |
|---|---|---|---|
| **points parameterisation** | affine-invariant, `remap_output='exp'` shipped | `exp`: `(x/z, y/z, logz) → (xy·e^{logz}, e^{logz})` | same, and the refiner predicts a **residual in logz** |
| **mask** | **raw logit**, no sigmoid; `infer` thresholds the *logit* at `0.5` | sigmoid probability, thresholded at `0.5` | same as V2 |
| **metric scale** | absent | `exp(MLP(cls))` | same |
| **CLS token** | unused | feeds the scale head | feeds the scale head |
| **refinement** | none | none | `refine_steps` sparse voxel updates |
| **focal/shift recovery** | once | once | **per step**, because refinement changes the 3D shape |

The V1 mask is the sharpest trap: `v1.forward` returns `{'points', 'mask'}` with the mask
un-activated, and `v1.infer` does `mask > self.mask_threshold` with
`mask_threshold=0.5` — i.e. a threshold *in logit space*. Port it faithfully and say so in
the README; do **not** "fix" it, and do not let the V2 habit of applying a sigmoid leak into
V1. A test that pins `MoGeV1`'s mask output as **unbounded** (a value outside `[0,1]`
survives a forward pass) is the guard.

## 9. Build, serialization and graph-safety contracts

### 9.1 The rules

* `__init__` creates every sub-layer with an explicit `name=`; `build()` materialises
  exactly what `call()` runs. Sub-layer lists stay **flat and paired by index** — a nested
  list of `[conv, upsample]` pairs is not saved by Keras and a round trip silently restored
  **none** of six kernels, measured max delta 17.3, no warning (DECISION D-027,
  `heads/vision/factory.py:354-359`). `ConvStack` has five parallel lists
  (`input_blocks`/`resamplers`/`res_blocks`/`output_blocks`) — flat by construction.
* **Force-build in `build()`**, not only in `load_own_variables`: a `.keras` reload runs
  `build()` but never `call()`, so a lazily built head loses its weights (omnipoint lost 8
  of 212; `omnipoint/model.py:331-350`). Heads that are `None` must be built **not at all**.
* `from_config` deserialises the nested encoder/head objects by `from_config`, never
  `clone_model` (which returns a plain Functional and would silently drop
  `DINOv2Backbone.tap`; `depth_anything/model.py:423-427`).
* Every constructor argument is in `get_config`, including `remap_output`,
  `num_tokens_range`, `mask_threshold` (V1), `refiner_depth_resolution`, `refine_steps`,
  `fp32_output_projection`, and every ConvStack dimension list.
* New `ValueError`s get a `from_config` substitute-and-warn migration path (v2 guide §6.3).
* Caches hold only pure functions of shape/dtype.

### 9.2 The MoGe-specific guards

| Claim | Guard shape |
|---|---|
| A `head=None` configuration builds **no** head weights | weight-path census against a `normal_head=None` model — an *absence* assertion, so it needs a **positive liveness arm** through the same detector (v2 guide §13.4.6) |
| Explicit build == lazy build | relative weight-path parity, both directions |
| A round trip preserves **values** | reloaded-vs-original output equality at `atol=0.0`, `rtol=0`, **before** the first call. Weight counts, weight paths, `count_params()` and the `.keras` md5 are each blind and have each passed on a broken archive (`GUIDE.md:46-52`) |
| The ConvTranspose resampler is zeroed outside `[0,0,0,0]` | weight-value assertion on the built kernel |
| The pixel-shuffle sub-pixel weights are tied | weight-value assertion |
| `exp` remap is applied **after** the resize and the permute | value assertion on a known coordinate tensor |
| V1's mask is a logit | a value outside `[0,1]` survives a forward pass |
| `refine_steps=0 == refine_steps=3` on a freshly built refiner | exact-equality assertion, enabled by `out_proj`'s zero init (§13.3) |

## 10. `infer()` and the geometry post-processing

`recover_focal_shift` is **not** graph-safe upstream either — it calls
`points.detach().cpu().numpy()` and then `scipy.optimize.least_squares`
(`geometry_torch.py::recover_focal_shift`). Keeping it out of `call()` is faithful, not a
compromise.

`utils/moge_geometry.py` (new, numpy/scipy — data-pipeline rules apply, never inside
`call()`):

* `recover_focal_shift(points, mask, focal=None, downsample_size=(64,64))` — 64×64 nearest
  downsample, per-batch `solve_optimal_focal_shift` / `solve_optimal_shift` via
  `scipy.optimize.least_squares`, and the documented degenerate case: **fewer than 2 valid
  samples ⇒ `(focal=1, shift=0)`**, never a raise and never NaN.
* `normalized_view_plane_uv(width, height, aspect_ratio)` — note the exact formula:
  `span_x = a/sqrt(1+a²)`, `span_y = 1/sqrt(1+a²)`, `u = linspace(−span_x·(W−1)/W, +…)`,
  `v = linspace(−span_y·(H−1)/H, +…)`, `meshgrid(indexing='xy')`. This grid is used as a
  *conditioning input* in V1/V2/V3 **and** as the least-squares basis in focal recovery, so
  the two must be the **same function**, not two copies.
* `intrinsics_from_focal_center(fx, fy, cx=0.5, cy=0.5)`, `depth_map_to_point_map`,
  `fov_to_focal`, `intrinsics_to_fov`, `dilate_with_mask` (used by the CLI's edge threshold).
* The focal round-trip that must be pinned numerically:
  `focal = a / sqrt(1+a²) / tan(fov_x/2)`, then
  `fx = focal/2 · sqrt(1+a²)/a`, `fy = focal/2 · sqrt(1+a²)`.

**Convention hazard, stated once and prominently:** MoGe's focal is *relative to half the
diagonal* and its intrinsics are *normalized*; `utils/camera_models.py` is *pixel*-space
with no normalized convention and its equirect path puts **+y up** while pinhole/fisheye put
**+y down**. Do **not** add a normalized-intrinsics mode to `camera_models` as a drive-by.
Keep MoGe's convention inside `utils/moge_geometry.py`, name the parameter
`focal_half_diagonal` rather than `fx`, and cross-reference both conventions in the
docstring.

`infer()` on the model is then a thin method: forward → `.numpy()` → the numpy helpers →
`+inf` masking. It is **not** `call()`, so it is allowed to leave the graph; make that
explicit in its docstring, and keep the model itself `predict`-safe.

## 11. The truncated-L1 alignment solver (D-2)

This is the actual supervision of the MoGe papers — "optimal training supervision" is in
the MoGe-1 title — so it gets ported exactly, not approximated.

`utils/alignment.py::align` solves `min_a Σ_i min(trunc, w_i·|a·x_i − y_i|)` in closed form
by sorting `y_i/x_i` and `B_i = (w_i y_i − trunc)/(w_i x_i)`, `C_i = (w_i y_i + trunc)/(w_i x_i)`,
evaluating the left/right derivatives via prefix sums, locating the sign change with
`searchsorted`, evaluating the objective at every extremum, and taking a segment-min. The
returned `a` is then re-expressed as `y[idx_2]/x[idx_2]` so the gradient path is short
(a deliberately two-gather reconstruction — mirror it, do not "simplify" it).

### 11.1 The obstacle, measured

`keras.ops.searchsorted` exists but the **TF backend rejects N-D sorted sequences**:

```
ValueError: `searchsorted` only supports 1-D sorted sequences.
You can use `keras.ops.vectorized_map` to extend it to N-D sequences.
Received: sorted_sequence.shape=(1, 4)
```

and only `keras/src/ops/numpy.py` implements it at all — the JAX and Torch backends do not.
`align_points_scale_z_shift` needs a `(batch, n)` × `(batch, n)` batched searchsorted with
`n = 3·align_resolution²` (up to 3·48² = 6912 at `align_resolution=48`) and
`batch` = number of valid pixels (thousands). The O(n²) "count how many sorted entries are
≤ v" broadcast fallback is ~10¹¹ comparisons — not viable. `keras.ops.vectorized_map` over
rows is the documented escape hatch but is a poor citizen under XLA/JAX.

### 11.2 The chosen implementation

`utils/sorting.py` (new):

* `rowwise_searchsorted(sorted_values, queries, side)` — merge-sort, O((n+m) log(n+m)) per
  row, pure `keras.ops`:
  * `'left'`  ⇒ build `keys = concat([queries, sorted_values])`, stable `argsort`, count of
    the sorted-part *before* each query via `cumsum(is_sorted_part) − 1`, then gather through
    the inverse permutation;
  * `'right'` ⇒ the mirror (`concat([sorted_values, queries])`), giving ties to the sorted
    side.
  Correctness oracle: **brute-force enumeration** of the sorted prefix
  (`sum(sorted <= q)` / `sum(sorted < q)`) on small random inputs, plus tie-heavy cases —
  and per §13.4.4 the oracle must consume the implementation's **post-cast** bits.
* `segment_argmin_via_score(x, segment_ids, num_segments)` — `keras.ops.scatter` is
  additive-only, and `scatter_reduce(reduce='amin')` has no `keras.ops` equivalent.
  Trick: `score = (−x)·BIG + (N − idx)` and `ops.segment_max(score)`, so the max is the
  minimum `x` with the **smallest** index among ties. Upstream torch returns the *first*
  minimum; document the tie difference rather than pretending it is identical.
* `pack_unique(keys)` — sort-based dedup + inverse map (§13.2 also needs it).

### 11.3 The alignment functions to port

| Function | Used by |
|---|---|
| `align(x, y, w, trunc)` | everything |
| `align_depth_scale`, `align_points_scale` | `scale_invariant_global_loss`, `align_points_scale_xyz_shift` |
| `align_points_scale_z_shift` | `affine_invariant_global_loss` (the headline term) |
| `align_points_scale_xyz_shift` | `affine_invariant_local_loss` (patch terms) |
| `align_points_z_shift`, `align_points_xyz_shift` | shift-invariant global loss |
| `align_depth_affine`, `align_depth_affine_irls` | optional |
| `align_depth_shift_with_scale` (Gauss-Newton, 5 iterations, `t_min = −min(p_scaled)`) | optional depth-space variant |
| `segment_robust_weighted_median`, `segment_align_shift` | `radial_partition_local_loss` |

Note the two `torch.no_grad()` blocks: the anchor search is solved under `stop_gradient` and
only the final two-gather reconstruction stays differentiable. Preserve that split exactly —
it is the difference between a short gradient graph and an O(anchors × n²) one.

`utils3d.pt.group_as_segments` (used by the radial loss) has no Keras analogue either; port
it as `group_segments(labels)` on top of `pack_unique` with a mixed-radix integer key
(`(dir_x, dir_y, dir_z, log_dist, batch)` → one int64), then argsort + boundary diff →
offsets + group ids. Pinned against a NumPy `np.unique(..., axis=0)` oracle.

### 12.1 Terms, and which MoGe version needs which

From `configs/train/{v1,v2,v3}.json` → `loss`, keyed **label type** then group then term:

| Term | v1 | v2 | v3 | Notes |
|---|---|---|---|---|

| `radial_partition_local_loss_rand_partition` (α = 4/16/64) | — | — | ✓ | random rotation + random global scale per call; `pred_partition_ratio=0.5` |
| `normal_loss` (cross-product angle, 4 quadrants, 1°/90°/3°) | ✓ | — | — | v1 only |
| `edge_loss` (angle between finite differences) | — | ✓ | ✓ | |
| `normal_map_loss` (squared angle) | — | ✓ (w 0.1) | ✓ | |
| `mask_l2_loss` / `mask_bce_loss` | ✓ (l2) | ✓ (bce 0.1) | ✓ (bce 0.1) | BCE takes a **probability** (`mask_bce_loss` applies BCE itself); l2 takes a raw value and ignores unlabelled pixels |
| `metric_scale_loss` / `metric_scale_l1_loss` | — | ✓ (mse 0.1) | ✓ | **log-space**, and only where `gt_scale > 0` |
| `silog_mse_loss`, `scale_invariant_global_loss`, `shift_invariant_global_loss`, `decoupled_shift_invariant_global_loss`, `l1_global_loss`, `normal_map_tv_loss` | optional, not in the shipped configs | | | port only if a config references them |

**Activation accounting, and a divergence from the house pattern.** `mask_bce_loss` applies
`binary_cross_entropy` to a **probability** (`mask_l2_loss` squares a raw value), because
V2/V3 already apply `sigmoid` inside `forward` and V1 does not. This is the *opposite* of
`omnipoint/heads.py:234-236` (DECISION D-010), where the head emits **linear logits** and
the loss uses `BinaryCrossentropy(from_logits=True)` — a sigmoid there would be applied
twice. Both are correct; they are different contracts. Do not "harmonise" MoGe onto D-010
without also changing the loss, and do not let the V1 head inherit the V2 sigmoid.

Per label type the shipped configs differ (A: global + 3 patch levels + edge; B: no
patch_64; C: global + patch_4 only; D: v3's full radial set **applied to all four steps**).
That per-type table belongs in the **trainer config**, not baked into a loss class.

### 12.2 The invariants every one of these must satisfy

* **`call()` returns `(batch,)`, never a scalar.** A scalar return is not "ignoring"
  `sample_weight` — Keras multiplies *before* reducing, so it yields
  `whole_batch_loss · mean(sample_weight)`, charging every row the batch aggregate and
  making `reduction=` dead. Pinned executably by
  `tests/test_losses/test_the_premature_scalar_family_is_pinned.py`.
* That family predicate is **structurally blind** to a whole-batch term added into an
  already-correct `(batch,)` vector. MoGe's losses *do* couple across the batch (the global
  scale is shared, the anchor sampling is a multinomial over the batch), so each MoGe loss
  needs the per-loss arm `loss(w=[1,…,1,0]) · B/(B−1) == loss(batch[:-1])`, as
  `tests/test_losses/test_goodhart_loss.py` does.
* Finite on a fully-masked sample (the `max(count, ε)` pattern of
  `_masked_mean_over_all_but_batch`), finite under `float64`, and finite under
  `mixed_float16` — where the house precedent is the fp32 up-cast at `dino_loss.py:1173`
  and epsilon floors at fp16's smallest normal, **not** an invented sentinel.
* Empty-mask and empty-patch paths return a finite `0`, never NaN
  (`affine_invariant_local_loss` has an explicit `num_nonempty_patches == 0` branch).
* Every reduction asserts finiteness rather than assuming it (v2 guide §10).
* A **numerical** arm: on a synthetic pair of point maps, verify the recovered `scale` and
  `shift` against the values used to construct them — a *value* assertion, because a loss
  that responds to its input is not thereby correct.

## 13. The V3 refiner (D-3)

### 13.1 What upstream is

`Sparse3DUNet` over sparse voxels `(b, i, j, z_bin)`:

* `_voxelize`: `logz = coord[...,2]`, `zq = round(logz · 256)`,
  `z_offset = amin` over `(B,H,W)`, `coords = stack([batch, i, j, zq − z_offset])`.
  Everything forced to fp32 — the z-binning is quantised at 1/256, finer than fp16 over the
  usual logz range, so binning in fp16 collapses voxels.
* `SubmanifoldConv3d(k=3)`: for each occupied voxel, sum over the 27 neighbours **that exist**
  at the same level. Implemented upstream by `flex_gemm` Triton kernels with a
  `NeighborCache` shared between the down pass and the symmetric up pass.
* `SparsePool3d(k=f, stride=f, reduce='mean')` down; `SparseUpsample3d(nearest)` up onto the
  **skip level's** coordinate set.
* `SparseResBlock3d`: `LayerNorm(eps=1e-6)` → SiLU → conv → SiLU → **conv2 zero-init** →
  `+ skip`.
* `out_proj` is **zero-initialised** (`init_weights`), so an untrained refiner is an exact
  identity — a free and strong test invariant (§9.2).
* Conditioning: `encoder_feature[batch, :, y, x]` sampled at the bottleneck coords.

**Repo reality: zero prior art.** `submanifold`, `sparse_conv`, `SparseConv`, `SparsePool`
return **0 files** repo-wide; `voxel` hits only prose in two regularisation layers and
SqueezeNet. `layers/geometric/` has `point_cloud_autoencoder`, `supernode_pooling`,
`sparse_depth_splat` — none is a submanifold sparse conv. Upstream is also CUDA-only
(`flex_gemm` → Triton; no macOS wheels).

### 13.2 The key simplification: level 0 needs no hashing

Because **every pixel contributes exactly one voxel**, at level 0
`M₀ = B·H·W` and the row id is `b·H·W + i·W + j` — analytically known, no dedup, no hash.
The level-0 feature tensor is therefore **dense `(B, H, W, C)`** plus a `logz` map, and a
submanifold 3×3×3 conv over it is:

> **9 spatial shifts × 3 z-tap masks**, where the tap at offset `(di, dj, dz)` is active only
> where `|z(neighbour pixel) − z(this pixel)| == dz` (for `dz != 0`) — since each neighbour
> pixel has exactly one z, at most one voxel per `(di,dj)` offset can match a given `dz`.

That is 9 gathers of a dense tensor plus 27 masked matmuls — no `searchsorted`, no scatter,
no `unique`. It is the fastest possible expression of level 0 and it is exactly equivalent
to the 27-offset sparse formulation.

Levels ≥ 1 are where it gets real: pooling groups fine voxels by `(i//f, j//f, z//f)` and the
output set is the *distinct* set of those keys. A column at level ℓ can hold up to `f^ℓ`
occupied bins, so a padded-dense `(B, H/2ˡ, W/2ˡ, K, C)` layout is **not** bounded, and
duplicating a coarse voxel once per contributing fine pixel is **wrong** (a submanifold conv
would then see the duplicates as zero-distance neighbours and weight by multiplicity).
Real sparse bookkeeping it is, from level 1 up.

### 13.3 The four primitives (`moge/refiner/sparse_ops.py`, pure functions)

| Primitive | Construction in `keras.ops` |
|---|---|
| `pack_unique(keys) -> (unique_sorted, inverse)` | `order = argsort(keys, stable)`; `is_new = concat([True, k[1:] != k[:-1]])`; `starts = mask`; `inverse = cumsum(is_new) − 1` gathered back through `order` |
| `neighbour_gather(unique_keys, inverse, offsets)` | `rowwise_searchsorted(unique_keys, key + offset)` then a validity mask `found_key == query` — the **same** searchsorted utility as §11.2 |
| `sparse_mean_pool(feats, coords, factor, out_shape)` | `ops.scatter` (additive) of `feats` and of a ones-column into the coarse bins, then divide by the count; mean over occupied neighbours only |
| `sparse_nearest_up(feats, coords, target_coords)` | gather at `coords // factor`, then re-index onto the skip set |

Plus one pleasant surprise: **`_sample_encoder_feature` needs no gather.** `encoder_downsample == prod(downsample_factors) == 16` and the bottleneck is at level 4, so `i_token = i_fine // 16` exactly — the encoder feature is a dense `(B, token_rows, token_cols, C)` tensor and the conditioning input is an integer index map into it. (The assertion
`point_cloud_h == encoder_h * encoder_downsample` in the reference is exactly this identity.)

### 13.4 Layers on top

`Sparse3DUNet` mirroring the reference structure exactly: `input_proj` (Linear on the 3 raw
coordinates) → 5 encoder stages of `SparseResBlock3d` with a `PoolDown` after each →
`encoder_fuse` (Linear 1026→512 on the sampled encoder feature) → `fuse_proj`
(`Linear→SiLU→Linear`) → bottleneck stage → 4 × [`NearestUp` + add skip + decoder stage] →
`out_proj` (Linear → 1). `model_channels = [32,64,128,256,512]`, `encoder_downsample = 16`,
asserted `== prod(downsample_factors)` as upstream does.

### 13.5 The training-state trap

`refiner_detach_backbone_until` compares a **step counter** to a threshold and decides
whether to `stop_gradient` the encoder feature. Reading a Python counter inside `call()`
folds to a constant at trace time (§11.2 of the v2 guide: "Python state that never reaches
the traced graph"). Model it as an explicit `call(..., detach_backbone=None)` argument that
resolves to the attribute when `None`, so Keras re-traces when it flips — the mechanism the
guide describes for any python-valued argument. `refiner_detach_backbone` (the per-call
boolean) is separate and is a plain argument.

### 13.6 Declared non-goals and limits

* **Dynamic `M` at every level ≥ 1.** Works under the TF backend in eager and under
  `tf.function` with `TensorSpec([None, …])`; **not** exportable to ONNX or XLA-static.
  Upstream carries the same class of limitation via its `onnx_compatible_mode` flag.
* **Speed.** 27 gathers + masked matmuls per conv layer, ~10 layers, ×`refine_steps`
  re-voxelisations per forward. Correctness-first, fp32 accumulation, tuned later. The
  upstream `NeighborCache` reuse across the down/up passes is an optimisation we skip.
* **No macOS parity claim** (upstream cannot run there either); no benchmark claim of any
  kind (§14).
* `flex_gemm`'s `masked_implicit_gemm` vs `implicit_gemm` channel-width switch is an
  implementation detail of the Triton kernel with no Keras counterpart; ignore it.

### 13.7 The fallback, decided in advance

If the primitives cannot pass their NumPy-oracle tests, or a full-resolution
`refine_steps=3` forward does not fit in memory at a usable resolution, the fallback is
**option (A)**: ship V3 with `refiner=None` (which is exactly what the upstream ctor does,
with `warnings.warn("Warning: refiner is not enabled.")`) and `refine_steps=0`, keeping the
`MoGeV3` architecture and the per-step output contract intact. This is recorded here, before
any code, precisely so that "we could not do it" is a plan and not an accident.

## 14. Trainer, data and eval

### 14.1 Trainer shape (D-6)

`src/train/moge/train_moge.py` (+ `train_moge3.py` for the refinement recipe), on the
**omnipoint** pattern, not Depth-Anything's:

* `MogeTrainingWrapper` that owns the term weights and `add_loss`s inside `call()`; the
  model compiled with **`loss=None`**. DECISION D-020: `compile(loss=<callable>)` over a
  nested output was *measured broken* — Keras 3.8's `CompileLoss.build` does
  `tree.map_structure(lambda x: loss, y_pred)` and broadcasts one loss instance onto every
  output slot, recomputing the shared scale per term. Save the **real** model, not the
  wrapper.
* `parse_arguments` must be the first statement of `main()` (exits 0 on `--help` and
  allocates nothing); `setup_gpu` → `_config_from_args` (smoke overrides applied **last**
  and logged) → `train_moge(config)`.
* `set_seeds(config.seed)` first; `create_callbacks(...)` returns `(callbacks, results_dir)`
  and the config is rewritten from it; `save_config_json` into the run dir; a failed save
  **fails the run**, a failed plot does not.
* Optimizer via `optimization/optimizer.py:84 optimizer_builder` with **three parameter
  groups** mirroring the shipped configs (v2: head `1e-4`, backbone `1e-5`; v3: head `1e-5`,
  refiner `2e-4`, backbone `5e-6`) — the head/backbone split is a real feature of MoGe's
  recipe, not a detail. `setup_mixed_precision` sets the *policy*; wrap the optimizer in
  `LossScaleOptimizer` for float16 at the call site, and remember bfloat16 needs no wrapper.
* `low_resolution_training_steps` (50000 for v1/v2, 0 for v3) is a real curriculum knob
  and a config field that must be *read* — `tests/test_train/test_config_fields_are_live.py`.
* v3 specifics: dual pipelines `norefine_data` / `refine_data` with `refine_ratio`,
  `refiner_detach_backbone_until`, `refine_steps`, and per-term `apply_steps` with the
  `fixed_scale` pin for the post-step-0 terms.

### 14.2 Data

Depth is stored as **logarithmic 16-bit PNG** (upstream `moge/utils/io.py::read_depth/
write_depth`), with NaN/Inf encoding invalid — that is the dataset format, not a convenience.
Instances are folders with `image.jpg`, `depth.png`, `meta.json` carrying **normalized**
intrinsics, listed in `.index.txt`. Augmentation: perspective sample/warp with
**reject-and-resample** on the warped-valid ratio, edge-aware depth warp (bilinear in
disparity, nearest for validity), flip, and jitter/dof/shot-noise/blur/jpeg. Per-dataset
knobs: `depth_unit`, `metric_from_meta`, `finite_depth_mask`, `fov_range_absolute`,
`fov_range_relative`, `center_augmentation`, `weight`, `label_type`.

The perspective warp uses this repo's `utils/homography.py` plus a warp;
`layers/spatial_layer.py`'s bilinear sampler is the graph-safe precedent. Warp depth in
**disparity** space, not metric space. Note that `layers/spatial_layer.py`'s
`coordinate_grid` defaults to `alignment='centers'` over `[-0.5, 0.5]` while
`utils/camera_models.py` puts pixel centres at `u = col + 0.5` — pick one and do not mix
them silently.

### 14.3 Eval

Upstream `moge/test/{metrics,dataloader,baseline}.py`: metric groups `global` / `metric` /
`local`; suites `moge2` / `moge3`; boundary-F1; per-segment local error with the global scale
plus a per-segment shift. `MGEBaselineInterface` is a small ABC worth mirroring for
Depth-Anything/Metric3D comparisons. This is P7-scope; the model port does not depend on it.
