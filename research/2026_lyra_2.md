## 1. What Lyra-2 is

Two-stage generative-reconstruction, single image → long video → explicit 3D:

| Stage | In | Out | Key files (upstream) |
|---|---|---|---|
| 1. Long-range video, WAN-14B-based DiT | image `480×832` + camera poses (81 frames recommended), optional text | temporally + spatially consistent video chunks (`g20` each step) | `_src/networks/wan2pt1_lyra2.py`, `_src/models/wan_t2v_model.py`, `_src/modules/conditioner.py,attention.py,umt5.py,clip.py,xlm_roberta.py`, `_src/tokenizers/wan2pt1.py`, `_src/schedulers/rectified_flow.py,self_forcing_scheduler.py`, `_src/models/fm_solvers_unipc.py` |
| Routing-only geometry | per-frame depth + poses + intrinsics | retrieved history ids + dense correspondence maps | `_src/datasets/depth_warp_dataloader.py,forward_warp_utils_pytorch.py,plucker_embed_corrupter.py`, `_src/inference/camera_traj_utils.py,camera_utils.py,depth_utils.py` |
| 2. Explicit 3D | generated video | 3D Gaussians `.ply` (+ mesh) | `_src/inference/vipe_da3_gs_recon.py,lyra2_zoomgs_inference.py,lyra2_custom_traj_inference.py` |
| Training harness | DL3DV-10K + VIPE + DAv3 depth + Qwen3 captions + T5 | DCP checkpoints | `scripts/train.py,convert_wan_checkpoint.py`, `_ext/imaginaire/trainer.py,config.py,checkpointer/dcp.py`, `_src/configs/,datasets/config_dataverse.py`, `_src/callbacks/` |

Per-Gaussian output (HF card): `mean(3) + scale(3) + quat(4) + color(3 or SH) + opacity(1)`.
Training cost (card + `TRAINING.md`): init from `Wan2.1-I2V-14B-480P` shards → 33 GB `.pth` (45 GB RAM converter), 32×H100 ×4000 iters (~24 B tokens), converges ~5000 iters on 64×B200. Runtime `WAN-2.1`, Linux, Ampere/Hopper/Blackwell (H100/GB200). Deps: `torch, accelerate, diffusers, peft, megatron-core, transformers, ninja` + `decord, av, imageio, webdataset, zarr, tensorstore` + MoGe via git + `OpenEXR, pyquaternion, jaxtyping`. None in `pyproject.toml` (`tensorflow==2.18.0, keras>=3.8,<4.0` only) — deliberate gap, see §5.

Loop at inference (`Fig.2`): user trajectory → (i) **retrieve** max-visibility history → (ii) **generate** next `g20` conditioned on temporal + spatial slots + warped correspondences → (iii) **update** 3D cache. Memory grows unbounded; consistency comes from routing, not longer attention.

## 2. Math and operations required to implement it

All symbols match the paper. This is the complete implementable core; App.A.1–A.4 hyperparameters (`d, δ, k, p_aug`, DiT width/depth, UniPC steps, DAv3 thresholds) were truncated in fetch (line 290/697) and must be transcribed from PDF + the five source files named in §2.8 before code.

### 2.1 Latent video diffusion + flow matching (Prelim, Eq.1)

Video `x ∈ R^{F×3×H×W}` → causal VAE `z=E(x) ∈ R^{F'×C×h×w}`. Wan-2.1 VAE: `8×` spatial, `4×` temporal, first frame independent:

```text
F' = floor((F-1)/4)+1, C=16, h=H/8, w=W/8
z_t = (1-t)·z_0 + t·ε, ε~N(0,I), t∈[0,1]
L = E[|| v_θ(z_t,t,c) − (ε − z_0) ||²]            (1)
```

`c` = text (T5 + CLIP) + camera. Long video = autoregressive fixed-length segments conditioned on history. Velocity target is constant `ε−z_0`; time sampling/weighting belongs in trainer, not loss.

### 2.2 Camera conditioning: depth-warp + Plücker

Per frame `i`: extrinsic `T_i=[R_i|t_i] ∈ R^{3×4}`, intrinsic `K_i ∈ R^{3×3}`, depth `D_i ∈ R^{H×W}`.

- Depth warp: forward-warp most recent `I_j` to each target `(T_i,K_i)` via `D_j`, encode, concat with denoise latent. Alone gives accurate control on Wan-2.1 but vanishes when no warped pixel lands → quality collapse.
- Plücker complement: per-pixel 6-D ray `r_i(u,v)=(d, o×d) ∈ R^6`, MLP-project to DiT width, add to token features. Survives drastic viewpoint change.

Both are needed; neither alone suffices.

### 2.3 FramePack context compression (Prelim, Eq.2)

Variable patchify by recency (small kernel recent, large kernel distant) + anchor `I_0` at full res:

```text
f1k1[anchor] f16k4 f2k2 f1k1[temporal] g20[generate]          (2)
```

`fnkm` = `n` frames subsampled `×m`. Anchor is the early-established endpoint preventing appearance drift.

### 2.4 3D cache (anti-forgetting, §4.2)

Per frame `i` with `(T_i,K_i,D_i)` store independently, never fuse:

- (a) full-res `D_i` + camera params (precision for correspondence);
- (b) downsampled cloud `P_i ∈ R^{(H/d)×(W/d)×3}` by subsampling `D_i` factor `d` then unprojecting to world.

No global point cloud: generated-frame depth degrades over time; fusion would bake misalignment into one corrupted reconstruction (ablation `w/ Global Point Cloud` loses camera-control 63.87→49.86).

### 2.5 Geometry-aware retrieval

Target `(T*,K*)`: project every `P_i` to target plane, per-pixel min-depth over all frames for occlusion. Point visible iff `depth − min_depth < δ`. Score `φ(i)` = visible-point count.

- Train: sample history ∝ `φ(i)` (robust to retrieval variance).
- Inference: greedy max-coverage to `N_s=5` — iteratively pick frame covering most not-yet-covered target pixels. Avoids redundant nearby views; recalls regions hundreds of frames old, far outside temporal window.

### 2.6 Spatial slots + canonical-coordinate warp (§4.2, Eq.3)

Retrieved `{I_j}_{j=0}^{N_s−1}` → VAE image tokens (no temporal compression) as spatial slots with same variable-kernel compression. Full layout:

```text
f1k1[anchor] f4k2 f1k1[spatial] f16k4 f2k2 f1k1[temporal] g20[generate]
```

Spatial = `N_s=5`: 4 frames `k2` + 1 frame `k1`, joint full self-attention with temporal + generate tokens.

Dense grounding via canonical warp (not RGB warp — warped RGB holes/stretch/bleed become a crutch the prior copies):

```text
C_j ∈ [-1,1]^{3×H×W}, channels (u, v, 2·j/N_s − 1)
Ĉ_j = FwdWarp(C_j, D_{s_j}, T_{s_j}, T*, K_{s_j}, K*)          (3)
```

Append warped depth as 4th channel `[Ĉ_j; D̂_j]` per slot; pad missing slots so model distinguishes empty. Positional-encode + learned MLP → add to tokens at **every** transformer block self-attn.

Context = (1) spatial-slot tokens + (2) warped `[Ĉ;D̂]` embeddings + (3) FramePack temporal history.

### 2.7 Self-augmentation (anti-drifting, §4.3, Eq.4–5)

Root cause = observation bias: train on clean history, infer on own imperfect outputs. FramePack anchoring alone does not close it.

Causal VAE: `z0_hist=E(x_hist)`, `z0_cur=E(x_cur|x_hist)` (cache dependency). With prob `p_aug`:

```text
z_t_hist = (1-t)·z0_hist + t·ε, t~U(0,0.5), ε~N(0,I)          (4)
z̃0_hist  = z_t_hist − t·v_θ(z_t_hist,t,c)  (one-step denoise) (5)
```

Replace conditioning with `z̃0_hist`; target `z0_cur` always encoded from **clean** cache; flow loss denoises toward clean despite corrupted context. Cost = one extra DiT forward (vs full 35-step bi-directional self-forcing). Ablation `w/o Self-Augmentation`: style-consistency 85.07→77.98, FID 51.33→55.15. Keep during DMD distillation.

Forward-warp + Plücker + FramePack + retrieval + canonical warp + self-aug is the full Stage-1 recipe. Omit any one and a published metric drops (Table 3: `w/o FramePack` style 80.61, `w/ Explicit Corr. Fusion` camera 57.29 — i.e. fusing RGB correspondences instead of routing hurts).

### 2.8 Reconstruction + mesh + distillation (§§4.4–4.5)

- 3DGS backbone = Depth Anything v3 feed-forward per-pixel 3DGS. Two changes: (a) Gaussian DPT head downsampled `k×k` → Gaussians `/k²` (high-res input, compact splats for streaming/real-time); (b) finetune on Lyra-generated scenes (bridges generative inconsistency gap; `Ours Full` beats `Ours+DAv3` on every 3D metric, LPIPS-P 0.381 vs 0.413).
- Mesh: hierarchical OpenVDB sparse grid (fine near viewpoints, coarse background); rasterize median Gaussian depth per view, normals = depth gradient → oriented point cloud → SDF on grid → marching cubes → stitch + decimate.
- Distilled: DMD teacher→student, 35→4 steps + CFG distilled to single pass, retain self-aug. ~13× per-step speedup, LPIPS/FID parity, camera-control small drop (63.87→58.12). Interactive path.
- Metrics to reproduce: SSIM/LPIPS/FID + WorldScore subjective-quality / style-consistency / camera-controllability + reprojection error (SLAM depth); 3D: LPIPS-G (render vs GT), LPIPS-P (render vs generated — consistency proxy), FID, subjective.

### 2.9 Data curation + train/infer contracts (§5.1, App.A)

- Data: DL3DV-10K long clips, ViPE poses, DAv3 per-frame depth, Qwen3-VL-8B captions. Sample 1000 frames/video. I2V 30%: first `L=80` from single frame. AR 70%: segment `s∈[0,S_max)`, `S_max=floor((T-1)/L)−1`, history `[0,s·L+1)`, target next `L`.
- Inference: `retrieve(N_s=5) → generate(g20, 35 steps / 4 distilled) → update cache → VIPE/DAv3 recon → .ply / mesh`. Input `480×832`, 81-frame pose chunks; output Gaussian struct above.

## 4. What must be newly written (and only that)

1. `plucker.py` — `r=(d,o×d)` from `(K,T,H,W)` in `keras.ops`, finite-guarded (use `camera_models.py` + `tensors.l2_normalize`).
2. `warp.py` — occlusion-aware `FwdWarp` (RGB for data/debug, canonical+depth for model path) as pure `keras.ops` helpers shared by `build/call/compute_output_shape`; scipy/least-squares recovery stays in trainer/app.
3. `retrieval.py` — `φ(i)` visibility + greedy max-coverage (`N_s=5`); NumPy-friendly, tested with synthetic clouds.
4. `canonical.py` — `C_j` construction, padding/mask for missing slots, pos-enc + MLP aggregator added every block.
5. `framepack.py` — variable-kernel patchify config (`f1k1/f4k2/f16k4/f2k2/g20`) over `patch_2d` factory.
6. `self_aug.py` — trainer-level corruption (Eq.4–5); loss stays `FlowMatchingVelocityLoss` on clean target.
7. `gaussians.py` — `.ply` struct + `k×k` head + compactness accounting; mesh via external OpenVDB (not in-tree).
8. `trajectories.py` — 81-frame pose chunking, interpolation, lookback/revisit eval trajectories.
9. `metrics_lyra.py` — LPIPS-P/G, style-consistency, camera-controllability, reprojection-error as plain functions.
10. `datasets_lyra.py` — `rgb.mp4 / pose.npz / intrinsics.npz / depth.zip / caption.pkl` frame-aligned loader + `all_filter.lst`.

Everything else reuses §3. Bespoke DiT blocks, third ViT, second sampler algebra, or second LPIPS are out of scope.

## 6. Risks / open items

- Full Keras 14B DiT is explicitly **not** proposed (weights, VRAM, megatron, CUDA kernels, DCP, Triton sparse, 64×B200 convergence). Thin routing + interface leaf is the most this repo can own; pixels stay in external torch checkpoint.
- Need PDF App.A + `wan2pt1_lyra2.py`, `rectified_flow.py`, `fm_solvers_unipc.py`, `forward_warp_utils_pytorch.py`, `plucker_embed_corrupter.py` to pin `d, δ, k, p_aug`, PE dims, UniPC/DMD steps before any code.
- External gaps: VIPE poses, DAv3 weights, Qwen3-VL captions, OpenVDB meshing, `WAN-2.1` runtime — all outside `pyproject.toml` by design; document as extras with local-path knobs.
- Eval: 1k-frame DL3DV + Tanks-and-Temples long-horizon protocol (frame ~800+), SLAM reprojection — reproduce as scripts, not unit tests.
