### Design Decisions (Documented in Code)

| Decision | Recorded At | Rationale |
|----------|-------------|-----------|
| `BaseMixtureLayer` is an **internal seam**, not public | `base.py` docstring, `__init__.py` | Prevents Liskov violations; `RBFLayer` has no `cluster_axis` or `'mixture'` reconstruction analogue |
| `output_mode` kwarg shared **by name only** — vocabularies are **disjoint** | `factory.py` D-003, D-012; `README.md` | `RBF: {'basis','normalized'}` vs `KMeans/GMM: {'assignments','mixture'}` — collapsing would reject RBF's legal values |
| `_ClusterAxisMixin` is **stateless**, reads attributes host sets | `base.py` | Enables mixin to win `compute_output_shape` via MRO without perturbing `Layer.__init__` |
| `_cluster_axis_arg` (pre-build) vs `cluster_axis` (post-build) **must not alias** | `base.py` D-005 | Serializing post-build value bakes in rank-specific axes; breaks cross-rank reload |
| `RBFLayer.gamma_init` resolved in `build()`, not `__init__` | `radial_basis_function.py` D-001 | Dimension-aware default (`1/D` for `'basis'`, `1.0` for `'normalized'`) — `__init__` doesn't know `D` |
| `RBFLayer` `'basis'` arm trains but **does not train well** (ceiling ~D=400) | `radial_basis_function.py`, `README.md` | Documented honestly with measured gradient floors; `'normalized'` is recommended |
| `KMeansLayer.centroid_regularizer` is **inert** (warns once) | `kmeans.py` D-015, `README.md` | Centroids are `trainable=False`; Keras only collects regularizer losses from trainable weights |
| `GMMLayer` low-rank = **factor analysis**, not PPCA | `gmm.py` D-002, D-003 | Residual diagonal `d_k` is free per-dimension; PPCA would constrain `d_k = σ²·1` |
| Isometric regularizer under low-rank acts on **residual diagonal only** | `gmm.py` D-002/D-003 | Non-identifiable split → penalizing diagonal pushes anisotropy into `U_k` (complementary) |
| Factory is **non-strict** (warns on unknown kwargs, never raises) | `factory.py` D-009 | Cross-plan decision in `plans/SYSTEM.md` — hardening requires measured bug |

## Layer-by-Layer Analysis

### 1. `RBFLayer` (`radial_basis_function.py`)

**Purpose**: Radial Basis Function layer with learnable centers + adaptive repulsion (loss-based)

**Key Characteristics**:
- **Standalone** — does NOT inherit `BaseMixtureLayer` (no `cluster_axis`, `'mixture'` mode meaningless)
- **Two output modes**: `'basis'` (raw Gaussian activations, unnormalized) and `'normalized'` (NRBF = softmax over unclipped exponents)
- **Trainable weights**: `centers` (units × D), `gamma_raw` (units,) → `gamma = softplus(gamma_raw)`
- **Repulsion**: Added as `add_loss` (mean squared threshold violation over off-diagonal pairs)
- **Mixed-precision safe**: `autocast=False` on weights, cast in/out in `call()`

**Critical Fixes (Documented)**:
- `gamma_init=None` resolved in `build()` per-mode: `1/D` for `'basis'`, `1.0` for `'normalized'` (D-001, D-008)
- `'normalized'` uses **softmax over unclipped exponent** — NOT `phi / sum(phi)` (which produces NaN under fp16) and NOT clipped exponent (which kills gradients at D>64)
- 50.0 exponent clip **retained** on `'basis'` arm as underflow floor (D-001)
- `MIN_USEFUL_GRADMAX = 1e-4` floor for gradient liveness assertions

**Known Limitations** (honestly documented):
- `'basis'` arm: gradients fall below 1e-4 at D≈512; useless at D=784 (flattened MNIST) and D=1024
- `'basis'` arm: requires ~standardized input (scale ~7 re-saturates clip at ANY D)
- `'basis'` arm: at identical hyperparams, loss 0.69 vs `'normalized'` 0.176 (chance = 0.693)
- `'normalized'` arm: softmax saturates at large gamma/scale; unclipped exponent overflows at `D*gamma*max|x|² > 3.4e38`

### 2. `KMeansLayer` (`kmeans.py`)

**Purpose**: Differentiable soft K-means with EMA centroid updates, momentum, and repulsion

**Key Characteristics**:
- **Inherits `BaseMixtureLayer`** → supports `cluster_axis` (multi-axis), `output_mode: 'assignments' | 'mixture'`
- **Centroids are `trainable=False`** — updated in-place via EMA inside `call()` when `training=True`
- **Centroid update**: `u = alive*(target - c) + repulsion(c)` → momentum-smoothed → `c += lr * m`
- **`alive` gate**: `cluster_mass > 1e-6` — zeros data pull for dead centroids, NOT repulsion
- **Repulsion**: Vector force between centroids (smoothed inside momentum, not added on top)
- **`centroid_regularizer`**: Accepted + serialized + **warns** — dead code (trainable=False)

**Critical Fixes**:
- Graph-safe training factor (`resolve_training_factor`) — handles symbolic `training` tensor
- `_MIN_CLUSTER_MASS = 1e-6` (not 1e-3) — 1e-3 freezes entire VQ codebooks at K≥1024
- `reset_centroids()` deliberately **unseeded** — stateless `keras.random.normal(seed=N)` would produce bit-identical draws
- `compute_output_shape` works pre-build (uses `_cluster_axis_arg`)
- `_setup_cluster_axes()` idempotent — re-derives from `_cluster_axis_arg`

**Known Limitations**:
- **Masks ignored** — padded timesteps contribute to EMA target
- **Single replica only** — `assign`/`assign_add` in `call()` is replica-local under `tf.distribute`

### 3. `GMMLayer` (`gmm.py`)

**Purpose**: Fully differentiable GMM with diagonal or low-rank covariances, isometric regularization

**Key Characteristics**:
- **Inherits `BaseMixtureLayer`** → `cluster_axis`, `output_mode: 'assignments' | 'mixture'`
- **All parameters trainable**: `means`, `log_variances`, `mixture_logits`, (+ `covariance_factors` under low-rank)
- **Two covariance types**: `'diagonal'` (default) and `'low_rank'` (factor analysis: `Σ = diag(d) + UUᵀ`)
- **Woodbury/Cholesky** for low-rank: no (D,D) materialization; batched `solve_triangular` with verified RHS convention
- **Isometric regularizer**: Penalizes per-component log-variance dispersion (mean squared deviation from per-component mean)
- **Variance bounds**: `variance_floor` (1e-3) and `_VARIANCE_CEILING = 1e6` (prevents `exp` overflow → NaN)

**Critical Fixes**:
- Low-rank `reset_parameters()` re-runs `factor_initializer` — zeroing `U` makes `dL/dU ≡ 0` (Woodbury quadratic at 0)
- `covariance_factors` created ONLY for `'low_rank'` — invariant I1: existing checkpoints stay weight-compatible
- `_log_effective_variances()` single source for diagonal density + isometric loss (R7)
- Isometric notice fires at INFO (not WARNING) for `low_rank` + `strength>0` — reframes semantics without crying wolf
- Low-rank equivalence tests: `U=0` collapses to diagonal; default config unchanged (backward compat)

## Issues & Recommendations

### Minor / Documentation

1. **`RBFLayer` repulsion loss formula in docstring** — The docstring shows `V_rep = α · mean_{i≠j} max(0, d_min·(1+μ) - ||cᵢ - cⱼ||)²` but code computes `repulsion_strength * sum(masked_penalty) / n_pairs` where `masked_penalty = max(0, threshold - dist)²` and `threshold = min_distance * (1 + safety_margin)`. This matches, but the docstring uses `μ` for `safety_margin` — consider aligning notation.

2. **`KMeansLayer` `_MIN_CLUSTER_MASS = 1e-6`** — Module-level constant; consider making it a class attribute for discoverability.

3. **`GMMLayer` `_VARIANCE_CEILING = 1e6`** — Same; module-level constant, not discoverable on the class.

### Potential Enhancements

1. **`RBFLayer` could support `cluster_axis`** — Would make it consistent with KMeans/GMM for multi-axis inputs, but README explicitly argues against this (no `'mixture'` analogue, basis layer not clusterer). Current design is intentional.

2. **`KMeansLayer` distributed training support** — Currently single-replica only. Could add `tf.distribute` strategy via `tf.distribute.get_strategy().extended.call_for_each_replica` + all-reduce, but would complicate the layer significantly.

3. **`GMMLayer` full covariance option** — Currently diagonal + low-rank. A `'full'` option would be `(K, D, D)` — expensive but sometimes needed. Low-rank is the practical sweet spot.

4. **Factory strictness toggle** — Other factories (attention, norms, ffn) are strict. The non-strict behavior is a deliberate cross-plan decision, but a `strict=False` parameter could let callers opt in to validation.

## Gradient Collapse at High Dimensions: Analysis & Proposed Solutions

### The Problem (Measured)

The `RBFLayer` `'basis'` mode suffers from **gradient collapse at high feature dimensions** due to the `1/D` gamma scaling:

| D (feature dim) | gradmax (centers) | gradmax (gamma_raw) | Status |
|----------------|-------------------|---------------------|--------|
| 128 | 3.56e-4 | 3.3e-2 | ✅ Above floor |
| 256 | 1.50e-4 | 3.4e-2 | ⚠️ Near floor |
| 384 | 1.14e-4 | 3.4e-2 | ⚠️ At floor |
| **512** | **8.52e-5** | 3.4e-2 | ❌ **Below 1e-4 floor** |
| **784** (MNIST flat) | **5.68e-5** | 3.4e-2 | ❌ **Dead** |
| **1024** | **3.78e-5** | 3.4e-2 | ❌ **Dead** |

**Root Cause**: `gamma = 1/D` → `dist_sq * gamma ≈ O(1)` keeps exponent in range, but `∂/∂c [exp(-gamma * ||x-c||²)] = -2*gamma*(x-c)*exp(...)` has `gamma = 1/D` factor → gradient shrinks as `1/D`.

**Why not larger `c/D`?** Measured at D=512: `c=1` → 8.3e-5, `c=4` → 9.6e-7, `c=8` → 1.5e-9. Larger constant makes it **strictly worse** because `exp(-c)` kills the signal.

---

### Proposed Solutions

#### Approach 1: Per-Dimension Gamma (Diagonal Precision) — **RECOMMENDED**

Replace scalar `gamma_k` per unit with vector `gamma_k ∈ ℝ^D` (diagonal precision matrix):

```python
# In __init__:
self.per_dim_gamma = kwargs.get('per_dim_gamma', False)

# In build():
if self.per_dim_gamma:
    gamma_shape = (self.units, self._feature_dim)
    gamma_init_val = 1.0 / float(self._feature_dim)  # per-dim default
else:
    gamma_shape = (self.units,)
    gamma_init_val = self._gamma_init_resolved  # scalar default

self.gamma_raw = self.add_weight(
    name='gamma_raw',
    shape=gamma_shape,
    initializer=keras.initializers.Constant(
        np.log(np.expm1(gamma_init_val)) if gamma_init_val <= _SOFTPLUS_LINEAR_THRESHOLD else gamma_init_val
    ),
    ...
)

# In call():
if self.per_dim_gamma:
    # dist_sq_per_dim: (batch, ..., units, D) via broadcasting
    diff = keras.ops.expand_dims(inputs, axis=-2) - self.centers  # (..., units, D)
    dist_sq_per_dim = keras.ops.square(diff)
    scaled_dist_sq = keras.ops.sum(dist_sq_per_dim * self.gamma, axis=-1)
else:
    dist_sq = pairwise_squared_distance(inputs, self.centers)
    scaled_dist_sq = dist_sq * self.gamma
```

**Advantages**:
- Directly addresses the `1/D` gradient factor by giving each dimension its own scale
- Learns feature relevance per RBF unit (interpretable)
- Doesn't change the kernel math or introduce new hyperparameters
- `'normalized'` mode already exists and works — this makes `'basis'` viable for high-D use cases needing unnormalized activations
- **Backward compatible**: default `per_dim_gamma=False` preserves current behavior exactly

**Cost**: `units × D` params instead of `units` (e.g., 8×784 = 6,272 vs 8 — negligible)

---

#### Approach 2: Learnable Temperature Parameter

Add a learnable global temperature that counters the `1/D` scaling:

```python
self.temp_raw = self.add_weight(shape=(), initializer='zeros', ...)  # softplus → ~1
temp = keras.activations.softplus(self.temp_raw) + 1e-3
scaled_dist_sq = dist_sq * self.gamma * temp
```

**Pros**: Single scalar, minimal overhead  
**Cons**: Could push exponent back into clip saturation; doesn't address per-dimension relevance

---

#### Approach 3: Alternative Kernels (No Exponential Decay)

| Kernel | Formula | Gradient Behavior |
|--------|---------|-------------------|
| **Inverse Multiquadric** | `1 / sqrt(1 + gamma * ||x-c||²)` | Polynomial decay, no `gamma` factor in gradient numerator |
| **Thin Plate Spline** | `||x-c||² * log(||x-c||)` | Grows with distance, different scaling |
| **Rational Quadratic** | `(1 + gamma * ||x-c||²)^(-alpha)` | Power law, tunable tail |

**Pros**: Fundamentally different gradient scaling  
**Cons**: Changes the layer's mathematical character; breaks backward compatibility

---

#### Approach 4: Input Normalization Layer (Preprocessing)

```python
class StandardizeInputs(keras.layers.Layer):
    def call(self, x):
        return (x - self.mean) / (self.std + 1e-6)
```

**Pros**: The `1/D` law **assumes** ~standardized input (doc: "Standardized input required")  
**Cons**: Preprocessing concern, not layer concern; could be user error

---

#### Approach 5: Hybrid — Normalized Output + Learnable Sharpening

```python
# 'normalized' mode already works at high D
# Add learnable sharpening post-softmax:
logits = -scaled_dist_sq / temp  # temp learnable, default 1
output = keras.ops.softmax(logits, axis=-1)
```

**Pros**: Keeps shift-invariance (gradients don't shrink with D)  
**Cons**: This is essentially what `'normalized'` mode does with `temperature` parameter

---

### Recommendation

**Approach 1 (Per-Dimension Gamma) is the cleanest fix** for `'basis'` mode at high D because:

1. **Directly addresses the root cause** — the `1/D` factor in the gradient
2. **Adds expressiveness** — learns per-dimension relevance per unit
3. **Minimal API change** — single boolean flag, backward compatible
4. **No new hyperparameters** — uses same initialization logic
5. **Preserves `'basis'` semantics** — unnormalized activations for downstream linear combination

The `'normalized'` mode already works at high D and should remain the default recommendation for most users. This enhancement makes `'basis'` viable for the niche cases that need raw RBF activations at high dimensions (e.g., as a feature map for a subsequent linear layer, or for KAN-style architectures).
